La herramienta bash queda disponible para el modelo; esta acción se rechaza.

Cadena de reglas coincidentes (orden de evaluación)

#PatrónDecisiónCarácterProcedencia
1*allownativa generalOpenCode 1.18.25
2*asknativa del agenteOpenCode 1.18.25 · agente plan
3git *allowdeclarada global…\opencode\opencode.json:12:7
4git push *denydeclarada del agente…\.opencode\agents\plan.md:6:3

Explicación

La regla 4 determina la decisión porque es la última de la cadena que coincide con «git push origin main». Las declaradas del agente se evalúan después de las globales y de las nativas, por lo que desplaza a las reglas 1, 2 y 3.
RIGE no lee las aprobaciones permanentes que el desarrollador concedió ante una solicitud de permiso. Una aprobación permanente no revierte una denegación declarada, pero sí evita que una acción sujeta a confirmación vuelva a solicitarla.

Variante: comando compuesto

Acción: git add . && git push
Comando compuesto: RIGE no informa una decisión, para no dar una respuesta incompleta.

5 · Detalle de un hallazgo

¿Dónde está el problema y por qué ocurre?

Declaración que anula una protección nativa · agente plan

Localización

C:\dev\proyecto-ejemplo\opencode.json:18:9

16 │ "agent": {
17 │   "plan": {
18 │     "permission": { "edit": "allow" }

Causa

El agente «plan» trae una regla nativa que deniega la edición de archivos. La declaración de la línea 18 se evalúa después de esa regla y la reemplaza, de modo que «plan» puede editar archivos. OpenCode no lo advierte.

*denynativa del agente · OpenCode 1.18.25
