prompt you, or be blocked.</p>\n71: <p>As of <code>v1.1.1</code>, the legacy <code>tools</code> boolean config is deprecated and has been merged into <code>permission</code>. The old <code>tools</code> config is still supported for backwards compatibility.</p>\n72: <hr />\n73: <h2 id=\"actions\">Actions</h2>\n74: <p>Each permission rule resolves to one of:</p>\n75: <ul>\n76: <li><code>\"allow\"</code> — run without approval</li>\n77: <li><code>\"ask\"</code> — prompt for approval</li>\n78: <li><code>\"deny\"</code> — block the action</li>\n79: </ul>\n80: <hr />\n81: <h2 id=\"auto-mode\">Auto mode</h2>\n82: <p>Start OpenCode with <code>--auto</code> to automatically approve permission requests that are not explicitly denied.</p>\n83: <pre><code class=\"language-bash\">opencode --auto\n84: </code></pre>\n85: <p>You can also use auto mode with <a href=\"cli.html#run\"><code>opencode run</code></a>.</p>\n86: <pre><code class=\"language-bash\">opencode run --auto &quot;Refactor this module&quot;\n87: </code></pre>\n88: <p>Explicit <code>\"deny\"</code> rules are still enforced. Auto mode only changes requests that would otherwise ask for approval.</p>\n89: <p>In the TUI, open the command palette and select <strong>Enable auto-approve permissions</strong> or <strong>Disable auto-approve permissions</strong> to change modes. When auto mode is active, the prompt displays a muted <code>auto</code> indicator next to the current agent.</p>\n90: <hr />\n91: <h2 id=\"configuration\">Configuration</h2>\n92: <p>You can set permissions globally (with <code>*</code>), and override specific tools.</p>\n93: <pre><code class=\"language-json\">{\n94:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n95:   &quot;permission&quot;: {\n96:     &quot;*&quot;: &quot;ask&quot;,\n97:     &quot;bash&quot;: &quot;allow&quot;,\n98:     &quot;edit&quot;: &quot;deny&quot;\n99:   }\n100: }\n101: </code></pre>\n102: <p>You can also set all permissions at once:</p>\n103: <pre><code class=\"language-json\">{\n104:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n105:   &quot;permission&quot;: &quot;allow&quot;\n106: }\n107: </code></pre>\n108: <hr />\n109: <h2 id=\"granular-rules-object-syntax\">Granular Rules (Object Syntax)</h2>\n110: <p>For most permissions, you can use an object to apply different actions based on the tool input.</p>\n111: <pre><code class=\"language-json\">{\n112:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n113:   &quot;permission&quot;: {\n114:     &quot;bash&quot;: {\n115:       &quot;*&quot;: &quot;ask&quot;,\n116:       &quot;git *&quot;: &quot;allow&quot;,\n117:       &quot;npm *&quot;: &quot;allow&quot;,\n118:       &quot;rm *&quot;: &quot;deny&quot;,\n119:       &quot;grep *&quot;: &quot;allow&quot;\n120:     },\n121:     &quot;edit&quot;: {\n122:       &quot;*&quot;: &quot;deny&quot;,\n123:       &quot;packages/web/src/content/docs/*.mdx&quot;: &quot;allow&quot;\n124:     }\n125:   }\n126: }\n127: </code></pre>\n128: <p>Rules are evaluated by pattern match, with the <strong>last matching rule winning</strong>. A common pattern is to put the catch-all <code>\"*\"</code> rule first, and more specific rules after it.</p>\n129: <h3 id=\"wildcards\">Wildcards</h3>\n130: <p>Permission patterns use simple wildcard matching:</p>\n131: <ul>\n132: <li><code>*</code> matches zero or more of any character</li>\n133: <li><code>?</code> matches exactly one character</li>\n134: <li>All other characters match literally</li>\n135: </ul>\n136: <h3 id=\"home-directory-expansion\">Home Directory Expansion</h3>\n137: <p>You can use <code>~</code> or <code>$HOME</code> at the start of a pattern to reference your home directory. This is particularly useful for <a href=\"#external-directories\"><code>external_directory</code></a> rules.</p>\n138: <ul>\n139: <li><code>~/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n140: <li><code>$HOME/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n141: <li><code>~</code> -&gt; <code>/Users/username</code></li>\n142: </ul>\n143: <h3 id=\"external-directories\">External Directories</h3>\n144: <p>Use <code>external_directory</code> to allow tool calls that touch paths outside the working directory where OpenCode was started. This applies to any tool that takes a path as input (for example <code>read</code>, <code>edit</code>, <code>glob</code>, <code>grep</code>, and many <code>bash</code> commands).</p>\n145: <p>Home expansion (like <code>~/...</code>) only affects how a pattern is written. It does not make an external path part of the current workspace, so paths outside the working directory must still be allowed via <code>external_directory</code>.</p>\n146: <p>For example, this allows access to everything under <code>~/projects/personal/</code>:</p>\n147: <pre><code class=\"language-json\">{\n148:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n149:   &quot;permission&quot;: {\n150:     &quot;external_directory&quot;: {\n151:       &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n152:     }\n153:   }\n154: }\n155: </code></pre>\n156: <p>Any directory allowed here inherits the same defaults as the current workspace. Since <a href=\"#defaults\"><code>read</code> defaults to <code>allow</code></a>, reads are also allowed for entries under <code>external_directory</code> unless overridden. Add explicit rules when a tool should be restricted in these paths, such as blocking edits while keeping reads:</p>\n157: <pre><code class=\"language-json\">{\n158:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n159:   &quot;permission&quot;: {\n160:     &quot;external_directory&quot;: {\n161:       &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n162:     },\n163:     &quot;edit&quot;: {\n164:       &quot;~/projects/personal/**&quot;: &quot;deny&quot;\n165:     }\n166:   }\n167: }\n168: </code></pre>\n169: <p>Keep the list focused on trusted paths, and layer extra allow or deny rules as needed for other tools (for example <code>bash</code>).</p>\n170: <hr />\n171: <h2 id=\"available-permissions\">Available Permissions</h2>\n172: <p>OpenCode permissions are keyed by tool name, plus a couple of safety guards:</p>\n173: <ul>\n174: <li><code>read</code> — reading a file (matches the file path)</li>\n175: <li><code>edit</code> — all file modifications (covers <code>edit</code>, <code>write</code>, <code>patch</code>)</li>\n176: <li><code>glob</code> — file globbing (matches the glob pattern)</li>\n177: <li><code>grep</code> — content
