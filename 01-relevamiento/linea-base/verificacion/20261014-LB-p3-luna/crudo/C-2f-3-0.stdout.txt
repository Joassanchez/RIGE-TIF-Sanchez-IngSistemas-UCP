Useful for running multiple instances on the same network.</li>\n318: <li><code>cors</code> - Additional origins to allow for CORS when using the HTTP server from a browser-based client. class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Configuration files are <strong>merged together</strong>, not replaced.</p>\n</div>\n<p>Configuration files are merged together, not replaced. Settings from the following config locations are combined. Later configs override earlier ones only for conflicting keys. Deploy a <code>.mobileconfig</code> via MDM (Jamf, Kandji, FleetDM) and the settings are enforced automatically.</p>\n<p>OpenCode checks these paths:</p>\n<ol>\n<li><code>/Library/Managed Preferences/&lt;user&gt;/ai.opencode.managed.plist</code></li>\n<li><code>/Library/Managed Preferences/ai.opencode.managed.plist</code></li>\n</ol>\n<p>The plist keys map directly to <code>opencode.json</code> fields. The OpenCode config keys go directly in the payload dict:</p>\n<pre><code class=\"language-xml\">&lt;?xml version=&quot;1.0&quot; encoding=&quot;UTF-8&quot;?&gt;\n&lt;!DOCTYPE plist PUBLIC &quot;-//Apple//DTD PLIST 1.0//EN&quot;\n  &quot;http://www.apple.com/DTDs/PropertyList-1.0.dtd&quot;&gt;\n&lt;plist version=&quot;1.0&quot;&gt;\n&lt;dict&gt;\n  &lt;key&gt;PayloadContent&lt;/key&gt;\n  &lt;array&gt;\n    &lt;dict&gt;\n      &lt;key&gt;PayloadType&lt;/key&gt;\n      &lt;string&gt;ai.opencode.managed&lt;/string&gt;\n      &lt;key&gt;PayloadIdentifier&lt;/key&gt;\n      &lt;string&gt;com.example.opencode.config&lt;/string&gt;\n      &lt;key&gt;PayloadUUID&lt;/key&gt;\n      &lt;string&gt;GENERATE-YOUR-OWN-UUID&lt;/string&gt;\n      &lt;key&gt;PayloadVersion&lt;/key&gt;\n      &lt;integer&gt;1&lt;/integer&gt;\n      &lt;key&gt;share&lt;/key&gt;\n      &lt;string&gt;disabled&lt;/string&gt;\n      &lt;key&gt;server&lt;/key&gt;\n      &lt;dict&gt;\n        &lt;key&gt;hostname&lt;/key&gt;\n        &lt;string&gt;127.0.0.1&lt;/string&gt;\n      &lt;/dict&gt;\n      &lt;key&gt;permission&lt;/key&gt;\n      &lt;dict&gt;\n        &lt;key&gt;*&lt;/key&gt;\n        &lt;string&gt;ask&lt;/string&gt;\n        &lt;key&gt;bash&lt;/key&gt;\n        &lt;dict&gt;\n          &lt;key&gt;*&lt;/key&gt;\n          &lt;string&gt;ask&lt;/string&gt;\n          &lt;key&gt;rm -rf *&lt;/key&gt;\n          &lt;string&gt;deny&lt;/string&gt;\n        &lt;/dict&gt;\n      &lt;/dict&gt;\n    &lt;/dict&gt;\n  &lt;/array&gt;\n  &lt;key&gt;PayloadType&lt;/key&gt;\n  &lt;string&gt;Configuration&lt;/string&gt;\n  &lt;key&gt;PayloadIdentifier&lt;/key&gt;\n  &lt;string&gt;com.example.opencode&lt;/string&gt;\n  &lt;key&gt;PayloadUUID&lt;/key&gt;\n  &lt;string&gt;GENERATE-YOUR-OWN-UUID&lt;/string&gt;\n  &lt;key&gt;PayloadVersion&lt;/key&gt;\n  &lt;integer&gt;1&lt;/integer&gt;\n&lt;/dict&gt;\n&lt;/plist&gt;\n</code></pre>\n<p>Generate unique UUIDs with <code>uuidgen</code>. Customize the settings to match your organization's requirements.</p>\n<p><strong>Deploying via MDM</strong></p>\n<ul>\n<li><strong>Jamf Pro:</strong> Computers &gt; Configuration Profiles &gt; Upload &gt; scope to target devices or smart groups</li>\n<li><strong>FleetDM:</strong> Add the <code>.mobileconfig</code> to your gitops repo under <code>mdm.macos_settings.custom_settings</code> and run <code>fleetctl apply</code></li>\n</ul>\n<p><strong>Verifying on a device</strong></p>\n<p>Double-click the <code>.mobileconfig</code> to install locally for testing (shows in System Settings &gt; Privacy &amp; Security &gt; Profiles), then run:</p>\n<pre><code class=\"language-bash\">opencode debug config\n</code></pre>\n<p>All managed preference keys appear in the resolved config and cannot be overridden by user or project configuration.</p>\n<hr />\n<h2 id=\"schema\">Schema</h2>\n<p>The server/runtime config schema is defined in <a href=\"https://opencode.ai/config.json\"><strong><code>opencode.ai/config.json</code></strong></a>.</p>\n<p>TUI config uses <a href=\"https://opencode.ai/tui.json\"><strong><code>opencode.ai/tui.json</code></strong></a>.</p>\n<p>Your editor should be able to validate and autocomplete based on the schema.</p>\n<hr />\n<h3 id=\"tui\">TUI</h3>\n<p>Use a dedicated <code>tui.json</code> (or <code>tui.jsonc</code>) file for TUI-specific settings.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n  &quot;scroll_speed&quot;: 3,\n  &quot;scroll_acceleration&quot;: {\n    &quot;enabled&quot;: true\n  },\n  &quot;diff_style&quot;: &quot;auto&quot;,\n  &quot;cursor&quot;: {\n    &quot;style&quot;: &quot;block&quot;,\n    &quot;blinking&quot;: true\n  },\n  &quot;mouse&quot;: true,\n  &quot;attention&quot;: {\n    &quot;enabled&quot;: true,\n    &quot;notifications&quot;: true,\n    &quot;sound&quot;: true,\n    &quot;volume&quot;: 0.4\n  }\n}\n</code></pre>\n<p>Use <code>OPENCODE_TUI_CONFIG</code> to point to a custom TUI config file.</p>\n<p>When <code>cursor.style</code> is <code>\"default\"</code>, the terminal default cursor is restored, so <code>cursor.blinking</code> has no effect.</p>\n<p>Set <code>attention.enabled</code> to turn on TUI desktop notifications and sounds. See <a href=\"tui.html#attention\">TUI attention</a>.</p>\n<p>Legacy <code>theme</code>, <code>keybinds</code>, and <code>tui</code> keys in <code>opencode.json</code> are deprecated and automatically migrated when possible.</p>\n<hr />\n<h3 id=\"server\">Server</h3>\n<p>You can configure server settings for the <code>opencode serve</code> and <code>opencode web</code> commands through the <code>server</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;server&quot;: {\n    &quot;port&quot;: 4096,\n    &quot;hostname&quot;: &quot;0.0.0.0&quot;,\n    &quot;mdns&quot;: true,\n    &quot;mdnsDomain&quot;: &quot;myproject.local&quot;,\n    &quot;cors&quot;: [&quot;http://localhost:5173&quot;]\n  }\n}\n</code></pre>\n<p>Available options:</p>\n<ul>\n<li><code>port</code> - Port to listen on.</li>\n<li><code>hostname</code> - Hostname to listen on. When <code>mdns</code> is enabled and no hostname is set, defaults to <code>0.0.0.0</code>.</li>\n<li><code>mdns</code> - Enable mDNS service discovery. This allows other devices on the network to discover your OpenCode server.</li>\n<li><code>mdnsDomain</code> - Custom domain name for mDNS service. Defaults to <code>opencode.local</code>. Useful for running multiple instances on the same network.</li>\n<li><code>cors</code> - Additional origins to allow for CORS when using the HTTP server from a browser-based client. Values must be full origins (scheme + host + optional port), eg <code>https://app.example.com</code>.</li>\n</ul>\n<p><a href=\"server.html\">Learn more about the server here</a>.</p>\n<hr />\n<h3 id=\"shell\">Shell</h3>\n<p>You can configure the shell used for the interactive terminal using the <code>shell</code> option. Compatible shells are also used for agent tool calls.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;shell&quot;: &quot;pwsh&quot;\n}\n</code></pre>\n<p>If not specified, OpenCode will automatically discover and use a sensible default based on your operating system (e.g. <code>pwsh</code> or <code>cmd.exe</code> on Windows, <code>/bin/zsh</code> or <code>/bin/bash</code> on macOS/Linux). You can provide an absolute path or a short name.</p>\n<hr />\n<h3 id=\"tools\">Tools</h3>\n<p>You can manage the tools an LLM can use through the <code>tools</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;tools&quot;: {\n    &quot;write&quot;: false,\n    &quot;bash&quot;: false\n  }\n}\n</code></pre>\n<p><a href=\"tools.html\">Learn more about tools here</a>.</p>\n<hr />\n<h3 id=\"models\">Models</h3>\n<p>You can configure the providers and models you want to use in your OpenCode config through the <code>provider</code>, <code>model</code> and <code>small_model</code> options.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {},\n  &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n  &quot;small_model&quot;: &quot;anthropic/claude-haiku-4-5&quot;\n}\n</code></pre>\n<p>The <code>small_model</code> option configures a separate model for lightweight tasks like title generation. By default, OpenCode tries to use a cheaper model if one is available from your provider, otherwise it falls back to your main model.</p>\n<p>Provider options can include <code>timeout</code>, <code>chunkTimeout</code>, and <code>setCacheKey</code>:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {\n    &quot;anthropic&quot;: {\n      &quot;options&quot;: {\n        &quot;timeout&quot;: 600000,\n        &quot;chunkTimeout&quot;: 30000,\n        &quot;setCacheKey&quot;: true\n      }\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>timeout</code> - Request timeout in milliseconds (default: 300000). Set to <code>false</code> to disable.</li>\n<li><code>chunkTimeout</code> - Timeout in milliseconds between streamed response chunks. If no chunk arrives in time, the request is aborted.</li>\n<li><code>setCacheKey</code> - Ensure a cache key is always set for designated provider.</li>\n</ul>\n<p>You can also configure <a href=\"models.html#local\">local models</a>. <a href=\"models.html\">Learn more</a>.</p>\n<hr />\n<h3 id=\"policies\">Policies</h3>\n<p>Use the <code>experimental.policies</code> option to allow or deny OpenCode actions on configured resources. Currently, policies can control which providers OpenCode may use.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;experimental&quot;: {\n    &quot;policies&quot;: [\n      {\n        &quot;effect&quot;: &quot;deny&quot;,\n        &quot;action&quot;: &quot;provider.use&quot;,\n        &quot;resource&quot;: &quot;openai&quot;\n      }\n    ]\n  }\n}\n</code></pre>\n<p><a href=\"policies.html\">Learn more about policies here</a>.</p>\n<hr />\n<h3 id=\"image-attachments\">Image attachments</h3>\n<p>OpenCode normalizes image attachments before sending them to the model. By default, images are resized when they exceed <code>2000x2000</code> pixels or <code>5242880</code> base64 bytes.</p>\n<p>Configure image attachment limits with the <code>attachment.image</code> option:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;attachment&quot;: {\n    &quot;image&quot;: {\n      &quot;auto_resize&quot;: true,\n      &quot;max_width&quot;: 2000,\n      &quot;max_height&quot;: 2000,\n      &quot;max_base64_bytes&quot;: 5242880\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>auto_resize</code> - Resize images that exceed the configured limits before provider requests. Set to <code>false</code> to reject oversized images instead.</li>\n<li><code>max_width</code> - Maximum image width in pixels before resizing or rejection.</li>\n<li><code>max_height</code> - Maximum image height in pixels before resizing or rejection.</li>\n<li><code>max_base64_bytes</code> - Maximum encoded image payload size. This is the base64 payload size, not the original file size.</li>\n</ul>\n<p>If an image still cannot fit after resizing, OpenCode omits oversized tool-result images or fails oversized user-provided images with an image size error.</p>\n<hr />\n<h4 id=\"provider-specific-options\">Provider-Specific Options</h4>\n<p>Some providers support additional configuration options beyond the generic <code>timeout</code> and <code>apiKey</code> settings.</p>\n<h5 id=\"amazon-bedrock\">Amazon Bedrock</h5>\n<p>Amazon Bedrock supports AWS-specific configuration:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {\n    &quot;amazon-bedrock&quot;: {\n      &quot;options&quot;: {\n        &quot;region&quot;: &quot;us-east-1&quot;,\n        &quot;profile&quot;: &quot;my-aws-profile&quot;,\n        &quot;endpoint&quot;: &quot;https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>region</code> - AWS region for Bedrock (defaults to <code>AWS_REGION</code> env var or <code>us-east-1</code>)</li>\n<li><code>profile</code> - AWS named profile from <code>~/.aws/credentials</code> (defaults to <code>AWS_PROFILE</code> env var)</li>\n<li><code>endpoint</code> - Custom endpoint URL for VPC endpoints. This is an alias for the generic <code>baseURL</code> option using AWS-specific terminology. If both are specified, <code>endpoint</code> takes precedence.</li>\n</ul>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Bearer tokens (<code>AWS_BEARER_TOKEN_BEDROCK</code> or <code>/connect</code>) take precedence over profile-based authentication. See <a href=\"providers.html#authentication-precedence\">authentication precedence</a> for details.</p>\n</div>\n<p><a href=\"providers.html#amazon-bedrock\">Learn more about Amazon Bedrock configuration</a>.</p>\n<hr />\n<h3 id=\"themes\">Themes</h3>\n<p>Set your UI theme in <code>tui.json</code>.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n  &quot;theme&quot;: &quot;tokyonight&quot;\n}\n</code></pre>\n<p><a href=\"themes.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"agents\">Agents</h3>\n<p>You can configure specialized agents for specific tasks through the <code>agent</code> option.</p>\n<pre><code class=\"language-jsonc\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;code-reviewer&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n      &quot;prompt&quot;: &quot;You are a code reviewer. Focus on security, performance, and maintainability.&quot;,\n      &quot;tools&quot;: {\n        // Disable file modification tools for review-only agent\n        &quot;write&quot;: false,\n        &quot;edit&quot;: false,\n      },\n    },\n  },\n}\n</code></pre>\n<p>You can also define agents using markdown files in <code>~/.config/opencode/agents/</code> or <code>.opencode/agents/</code>. <a href=\"agents.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"default-agent\">Default agent</h3>\n<p>You can set the default agent using the <code>default_agent</code> option. This determines which agent is used when none is explicitly specified.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;default_agent&quot;: &quot;plan&quot;\n}\n</code></pre>\n<p>The default agent must be a primary agent (not a subagent). This can be a built-in agent like <code>\"build\"</code> or <code>\"plan\"</code>, or a <a href=\"agents.html\">custom agent</a> you've defined. If the specified agent doesn't exist or is a subagent, OpenCode will fall back to <code>\"build\"</code> with a warning.</p>\n<p>This setting applies across all interfaces: TUI, CLI (<code>opencode run</code>), desktop app, and GitHub Action.</p>\n<hr />\n<h3 id=\"subagent-depth\">Subagent depth</h3>\n<p>You can control how deeply subagents can invoke other subagents using the <code>subagent_depth</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;subagent_depth&quot;: 2\n}\n</code></pre>\n<p>The default is <code>1</code>, which allows primary agents to launch subagents but prevents those subagents from launching additional subagents. Set it to <code>2</code> to allow one additional level of nested subagents, or <code>0</code> to prevent all subagent launches.</p>\n<hr />\n<h3 id=\"sharing\">Sharing</h3>\n<p>You can configure the <a href=\"share.html\">share</a> feature through the <code>share</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;share&quot;: &quot;manual&quot;\n}\n</code></pre>\n<p>This takes:</p>\n<ul>\n<li><code>\"manual\"</code> - Allow manual sharing via commands (default)</li>\n<li><code>\"auto\"</code> - Automatically share new conversations</li>\n<li><code>\"disabled\"</code> - Disable sharing entirely</li>\n</ul>\n<p>By default, sharing is set to manual mode where you need to explicitly share conversations using the <code>/share</code> command.</p>\n<hr />\n<h3 id=\"commands\">Commands</h3>\n<p>You can configure custom commands for repetitive tasks through the <code>command</code> option.</p>\n<pre><code class=\"language-jsonc\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;command&quot;: {\n    &quot;test&quot;: {\n      &quot;template&quot;: &quot;Run the full test suite with coverage report and show any failures.\\nFocus on the failing tests and suggest fixes.&quot;,\n      &quot;description&quot;: &quot;Run tests with coverage&quot;,\n      &quot;agent&quot;: &quot;build&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-5&quot;,\n    },\n    &quot;component&quot;: {\n      &quot;template&quot;: &quot;Create a new React component named $ARGUMENTS with TypeScript support.\\nInclude proper typing and basic structure.&quot;,\n      &quot;description&quot;: &quot;Create a new component&quot;,\n    },\n  },\n}\n</code></pre>\n<p>You can also define commands using markdown files in <code>~/.config/opencode/commands/</code> or <code>.opencode/commands/</code>. <a href=\"commands.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"keybinds\">Keybinds</h3>\n<p>Customize TUI keyboard shortcuts in <code>tui.json</code> with <code>keybinds</code>.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n  &quot;keybinds&quot;: {\n    &quot;command_list&quot;: &quot;ctrl+p&quot;\n  }\n}\n</code></pre>\n<p><code>keybinds</code> is merged with built-in defaults, so you only need to configure the shortcuts you want to change.</p>\n<p><a href=\"keybinds.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"snapshot\">Snapshot</h3>\n<p>OpenCode uses snapshots to track file changes during agent operations, enabling you to undo and revert changes within a session. Snapshots are enabled by default.</p>\n<p>For large repositories or projects with many submodules, the snapshot system can cause slow indexing and significant disk usage as it tracks all changes using an internal git repository. You can disable snapshots using the <code>snapshot</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;snapshot&quot;: false\n}\n</code></pre>\n<p>Note that disabling snapshots means changes made by the agent cannot be rolled back through the UI.</p>\n<hr />\n<h3 id=\"autoupdate\">Autoupdate</h3>\n<p>OpenCode will automatically download any new updates when it starts up. You can disable this with the <code>autoupdate</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;autoupdate&quot;: false\n}\n</code></pre>\n<p>If you don't want updates but want to be notified when a new version is available, set <code>autoupdate</code> to <code>\"notify\"</code>.\nNotice that this only works if it was not installed using a package manager such as Homebrew.</p>\n<hr />\n<h3 id=\"formatters\">Formatters</h3>\n<p>You can enable and configure code formatters through the <code>formatter</code> option. Omit it to keep formatters disabled.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;formatter&quot;: true\n}\n</code></pre>\n<p>Use an object to keep built-ins enabled while configuring overrides or custom formatters.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;formatter&quot;: {\n    &quot;prettier&quot;: {\n      &quot;disabled&quot;: true\n    },\n    &quot;custom-prettier&quot;: {\n      &quot;command&quot;: [&quot;npx&quot;, &quot;prettier&quot;, &quot;--write&quot;, &quot;$FILE&quot;],\n      &quot;environment&quot;: {\n        &quot;NODE_ENV&quot;: &quot;development&quot;\n      },\n      &quot;extensions&quot;: [&quot;.js&quot;, &quot;.ts&quot;, &quot;.jsx&quot;, &quot;.tsx&quot;]\n    }\n  }\n}\n</code></pre>\n<p><a href=\"formatters.html\">Learn more about formatters here</a>.</p>\n<hr />\n<h3 id=\"lsp-servers\">LSP Servers</h3>\n<p>You can enable and configure LSP servers through the <code>lsp</code> option. Omit it to keep LSP disabled.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;lsp&quot;: true\n}\n</code></pre>\n<p>Use an object to keep built-ins enabled while configuring overrides or custom LSP servers.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;lsp&quot;: {\n    &quot;typescript&quot;: {\n      &quot;disabled&quot;: true\n    }\n  }\n}\n</code></pre>\n<p><a href=\"lsp.html\">Learn more about LSP servers here</a>.</p>\n<hr />\n<h3 id=\"permissions\">Permissions</h3>\n<p>By default, opencode <strong>allows all operations</strong> without requiring explicit approval. You can change this using the <code>permission</code> option.</p>\n<p>For example, to ensure that the <code>edit</code> and <code>bash</code> tools require user approval:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;edit&quot;: &quot;ask&quot;,\n    &quot;bash&quot;: &quot;ask&quot;\n  }\n}\n</code></pre>\n<p><a href=\"permissions.html\">Learn more about permissions here</a>.</p>\n<hr />\n<h3 id=\"compaction\">Compaction</h3>\n<p>You can control context compaction behavior through the <code>compaction</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;compaction&quot;: {\n    &quot;auto&quot;: true,\n    &quot;prune&quot;: false,\n    &quot;reserved&quot;: 10000\n  }\n}\n</code></pre>\n<ul>\n<li><code>auto</code> - Automatically compact the session when context is full (default: <code>true</code>).</li>\n<li><code>prune</code> - Remove old tool outputs to save tokens (default: <code>false</code>). They allow you to create focused tools with custom prompts, models, and tool access.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Use the plan agent to analyze code and review suggestions without making any code changes.</p>\n</div>\n<p>You can switch between agents during a session or invoke them with the <code>@</code> mention.</p>\n<hr />\n<h2 id=\"types\">Types</h2>\n<p>There are two types of agents in OpenCode; primary agents and subagents.</p>\n<hr />\n<h3 id=\"primary-agents\">Primary agents</h3>\n<p>Primary agents are the main assistants you interact with directly. You can cycle through them using the <strong>Tab</strong> key, or your configured <code>switch_agent</code> keybind. These agents handle your main conversation. Tool access is configured via permissions — for example, Build has all tools enabled while Plan is restricted.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>You can use the <strong>Tab</strong> key to switch between primary agents during a session.</p>\n</div>\n<p>OpenCode comes with two built-in primary agents, <strong>Build</strong> and <strong>Plan</strong>. We'll\nlook at these below.</p>\n<hr />\n<h3 id=\"subagents\">Subagents</h3>\n<p>Subagents are specialized assistants that primary agents can invoke for specific tasks. You can also manually invoke them by <strong>@ mentioning</strong> them in your messages.</p>\n<p>OpenCode comes with three built-in subagents, <strong>General</strong>, <strong>Explore</strong>, and <strong>Scout</strong>. We'll look at this below.</p>\n<hr />\n<h2 id=\"built-in\">Built-in</h2>\n<p>OpenCode comes with two built-in primary agents and three built-in subagents.</p>\n<hr />\n<h3 id=\"use-build\">Use build</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Build is the <strong>default</strong> primary agent with all tools enabled. This is the standard agent for development work where you need full access to file operations and system commands.</p>\n<hr />\n<h3 id=\"use-plan\">Use plan</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>A restricted agent designed for planning and analysis. We use a permission system to give you more control and prevent unintended changes.\nBy default, all of the following are set to <code>ask</code>:</p>\n<ul>\n<li><code>file edits</code>: All writes, patches, and edits</li>\n<li><code>bash</code>: All bash commands</li>\n</ul>\n<p>This agent is useful when you want the LLM to analyze code, suggest changes, or create plans without making any actual modifications to your codebase.</p>\n<hr />\n<h3 id=\"use-general\">Use general</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A general-purpose agent for researching complex questions and executing multi-step tasks. Has full tool access (except todo), so it can make file changes when needed. Use this to run multiple units of work in parallel.</p>\n<hr />\n<h3 id=\"use-explore\">Use explore</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A fast, read-only agent for exploring codebases. Cannot modify files. Use this when you need to quickly find files by patterns, search code for keywords, or answer questions about the codebase.</p>\n<hr />\n<h3 id=\"use-scout\">Use scout</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A read-only agent for external docs and dependency research. Use this when you need to clone a dependency repository into OpenCode's managed cache, inspect library source, or cross-reference local code against upstream implementations without modifying your workspace.</p>\n<hr />\n<h3 id=\"use-compaction\">Use compaction</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that compacts long context into a smaller summary. It runs automatically when needed and is not selectable in the UI.</p>\n<hr />\n<h3 id=\"use-title\">Use title</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that generates short session titles. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h3 id=\"use-summary\">Use summary</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that creates session summaries. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h2 id=\"usage\">Usage</h2>\n<ol>\n<li>\n<p>For primary agents, use the <strong>Tab</strong> key to cycle through them during a session. You can also use your configured <code>switch_agent</code> keybind.</p>\n</li>\n<li>\n<p>Subagents can be invoked:\n   - <strong>Automatically</strong> by primary agents for specialized tasks based on their descriptions.\n   - Manually by <strong>@ mentioning</strong> a subagent in your message. For example.</p>\n<p><code>txt\n @general help me search for this function</code></p>\n</li>\n<li>\n<p><strong>Navigation between sessions</strong>: When subagents create child sessions, use <code>session_child_first</code> (default: <strong>\\<Leader>+Down</strong>) to enter the first child session from the parent.</p>\n</li>\n<li>\n<p>Once you are in a child session, use:\n   - <code>session_child_cycle</code> (default: <strong>Right</strong>) to cycle to the next child session\n   - <code>session_child_cycle_reverse</code> (default: <strong>Left</strong>) to cycle to the previous child session\n   - <code>session_parent</code> (default: <strong>Up</strong>) to return to the parent session</p>\n</li>\n</ol>\n<p>This lets you switch between the main conversation and specialized subagent work.</p>\n<hr />\n<h2 id=\"configure\">Configure</h2>\n<p>You can customize the built-in agents or create your own through configuration. Agents can be configured in two ways:</p>\n<hr />\n<h3 id=\"json\">JSON</h3>\n<p>Configure agents in your <code>opencode.json</code> config file:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n      &quot;prompt&quot;: &quot;{file:./prompts/build.txt}&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;allow&quot;,\n        &quot;bash&quot;: &quot;allow&quot;\n      }\n    },\n    &quot;plan&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;deny&quot;,\n        &quot;bash&quot;: &quot;deny&quot;\n      }\n    },\n    &quot;code-reviewer&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n      &quot;mode&quot;: &quot;subagent&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n      &quot;prompt&quot;: &quot;You are a code reviewer. Focus on security, performance, and maintainability.&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;deny&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<hr />\n<h3 id=\"markdown\">Markdown</h3>\n<p>You can also define agents using markdown files. Place them in:</p>\n<ul>\n<li>Global: <code>~/.config/opencode/agents/</code></li>\n<li>Per-project: <code>.opencode/agents/</code></li>\n</ul>\n<pre><code class=\"language-markdown\">---\ndescription: Reviews code for quality and best practices\nmode: subagent\nmodel: anthropic/claude-sonnet-4-20250514\ntemperature: 0.1\npermission:\n  edit: deny\n  bash: deny\n---\n\nYou are in code review mode. Focus on:\n\n- Code quality and best practices\n- Potential bugs and edge cases\n- Performance implications\n- Security considerations\n\nProvide constructive feedback without making direct changes.\n</code></pre>\n<p>The markdown file name becomes the agent name. For example, <code>review.md</code> creates a <code>review</code> agent.</p>\n<hr />\n<h2 id=\"options\">Options</h2>\n<p>Let's look at these configuration options in detail.</p>\n<hr />\n<h3 id=\"description\">Description</h3>\n<p>Use the <code>description</code> option to provide a brief description of what the agent does and when to use it.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n    }\n  }\n}\n</code></pre>\n<p>This is a <strong>required</strong> config option.</p>\n<hr />\n<h3 id=\"temperature\">Temperature</h3>\n<p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code> config.</p>\n<p>Lower values make responses more focused and deterministic, while higher values increase creativity and variability.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;temperature&quot;: 0.1\n    },\n    &quot;creative&quot;: {\n      &quot;temperature&quot;: 0.8\n    }\n  }\n}\n</code></pre>\n<p>Temperature values typically range from 0.0 to 1.0:</p>\n<ul>\n<li><strong>0.0-0.2</strong>: Very focused and deterministic responses, ideal for code analysis and planning</li>\n<li><strong>0.3-0.5</strong>: Balanced responses with some creativity, good for general development tasks</li>\n<li><strong>0.6-1.0</strong>: More creative and varied responses, useful for brainstorming and exploration</li>\n</ul>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;analyze&quot;: {\n      &quot;temperature&quot;: 0.1,\n      &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n    },\n    &quot;build&quot;: {\n      &quot;temperature&quot;: 0.3\n    },\n    &quot;brainstorm&quot;: {\n      &quot;temperature&quot;: 0.7,\n      &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen models.</p>\n<hr />\n<h3 id=\"max-steps\">Max steps</h3>\n<p>Control the maximum number of agentic iterations an agent can perform before being forced to respond with text only. This allows users who wish to control costs to set a limit on agentic actions.</p>\n<p>If this is not set, the agent will continue to iterate until the model chooses to stop or the user interrupts the session.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;quick-thinker&quot;: {\n      &quot;description&quot;: &quot;Fast reasoning with limited iterations&quot;,\n      &quot;prompt&quot;: &quot;You are a quick thinker. Solve problems with minimal steps.&quot;,\n      &quot;steps&quot;: 5\n    }\n  }\n}\n</code></pre>\n<p>When the limit is reached, the agent receives a special system prompt instructing it to respond with a summarization of its work and recommended remaining tasks.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Caution</div>\n<p>The legacy <code>maxSteps</code> field is deprecated. Use <code>steps</code> instead.</p>\n</div>\n<hr />\n<h3 id=\"disable\">Disable</h3>\n<p>Set to <code>true</code> to disable the agent.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;disable&quot;: true\n    }\n  }\n}\n</code></pre>\n<hr />\n<h3 id=\"prompt\">Prompt</h3>\n<p>Specify a custom system prompt file for this agent with the <code>prompt</code> config. The prompt file should contain instructions specific to the agent's purpose.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;prompt&quot;: &quot;{file:./prompts/code-review.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>This path is relative to where the config file is located. So this works for both the global OpenCode config and the project specific config.</p>\n<hr />\n<h3 id=\"model\">Model</h3>\n<p>Use the <code>model</code> config to override the model for this agent. Useful for using different models optimized for different tasks. For example, a faster model for planning, a more capable model for implementation.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>If you don’t specify a model, primary agents use the <a href=\"config.html#models\">model globally configured</a> while subagents will use the model of the primary agent that invoked the subagent.</p>\n</div>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;\n    }\n  }\n}\n</code></pre>\n<p>The model ID in your OpenCode config uses the format <code>provider/model-id</code>. For example, if you're using <a href=\"zen.html\">OpenCode Zen</a>, you would use <code>opencode/gpt-5.1-codex</code> for GPT 5.1 Codex.</p>\n<hr />\n<h3 id=\"tools-deprecated\">Tools (deprecated)</h3>\n<p><code>tools</code> is <strong>deprecated</strong>. Prefer the agent's <a href=\"#permissions\"><code>permission</code></a> field for new configs, updates and more fine-grained control.</p>\n<p>Allows you to control which tools are available in this agent. You can enable or disable specific tools by setting them to <code>true</code> or <code>false</code>. In an agent's <code>tools</code> config, <code>true</code> is equivalent to <code>{\"*\": \"allow\"}</code> permission and <code>false</code> is equivalent to <code>{\"*\": \"deny\"}</code> permission.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;tools&quot;: {\n    &quot;write&quot;: true,\n    &quot;bash&quot;: true\n  },\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;tools&quot;: {\n        &quot;write&quot;: false,\n        &quot;bash&quot;: false\n      }\n    }\n  }\n}\n</code></pre>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>The agent-specific config overrides the global config.</p>\n</div>\n<p>You can also use wildcards in legacy <code>tools</code> entries to control multiple tools at once. For example, to disable all tools from an MCP server:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;readonly&quot;: {\n      &quot;tools&quot;: {\n        &quot;mymcp_*&quot;: false,\n        &quot;write&quot;: false,\n        &quot;edit&quot;: false\n      }\n    }\n  }\n}\n</code></pre>\n<p><a href=\"tools.html\">Learn more about tools</a>.</p>\n<hr />\n<h3 id=\"permissions\">Permissions</h3>\n<p>You can configure permissions to manage what actions an agent can take. Each permission key can be set to:</p>\n<ul>\n<li><code>\"ask\"</code> — Prompt for approval before running the tool</li>\n<li><code>\"allow\"</code> — Allow all operations without approval</li>\n<li><code>\"deny\"</code> — Disable the tool</li>\n</ul>\n<p>The available permission keys are:</p>\n<table>\n<thead>\n<tr>\n<th>Key</th>\n<th>Tools it gates</th>\n</tr>\n</thead>\n<tbody>\n<tr>\n<td><code>read</code></td>\n<td><code>read</code></td>\n</tr>\n<tr>\n<td><code>edit</code></td>\n<td><code>write</code>, <code>edit</code>, <code>apply_patch</code></td>\n</tr>\n<tr>\n<td><code>glob</code></td>\n<td><code>glob</code></td>\n</tr>\n<tr>\n<td><code>grep</code></td>\n<td><code>grep</code></td>\n</tr>\n<tr>\n<td><code>list</code></td>\n<td><code>list</code></td>\n</tr>\n<tr>\n<td><code>bash</code></td>\n<td><code>bash</code></td>\n</tr>\n<tr>\n<td><code>task</code></td>\n<td><code>task</code></td>\n</tr>\n<tr>\n<td><code>external_directory</code></td>\n<td>Any tool that reads or writes files outside the project worktree</td>\n</tr>\n<tr>\n<td><code>todowrite</code></td>\n<td><code>todowrite</code>, <code>todoread</code></td>\n</tr>\n<tr>\n<td><code>webfetch</code></td>\n<td><code>webfetch</code></td>\n</tr>\n<tr>\n<td><code>websearch</code></td>\n<td><code>websearch</code></td>\n</tr>\n<tr>\n<td><code>lsp</code></td>\n<td><code>lsp</code></td>\n</tr>\n<tr>\n<td><code>skill</code></td>\n<td><code>skill</code></td>\n</tr>\n<tr>\n<td><code>question</code></td>\n<td><code>question</code></td>\n</tr>\n<tr>\n<td><code>doom_loop</code></td>\n<td>Recovery prompts when an agent appears stuck</td>\n</tr>\n</tbody>\n</table>\n<p><code>read</code>, <code>edit</code>, <code>glob</code>, <code>grep</code>, <code>list</code>, <code>bash</code>, <code>task</code>, <code>external_directory</code>, <code>lsp</code>, and <code>skill</code> accept either a shorthand action (<code>\"allow\" | \"ask\" | \"deny\"</code>) or an object of glob/pattern → action for fine-grained control. The remaining keys accept the shorthand action only.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Permission keys are matched as wildcard patterns against the underlying tool name, so the same syntax works for built-ins, custom tools, and MCP tools — for example <code>\"mymcp_*\": \"deny\"</code> denies every tool from an MCP server, and <code>\"mymcp_search\": \"ask\"</code> targets a single one.</p>\n</div>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;edit&quot;: &quot;deny&quot;\n  }\n}\n</code></pre>\n<p>You can override these permissions per agent.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;edit&quot;: &quot;deny&quot;\n  },\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;ask&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<p>You can also set permissions in Markdown agents.</p>\n<pre><code class=\"language-markdown\">---\ndescription: Code review without edits\nmode: subagent\npermission:\n  edit: deny\n  bash:\n    &quot;*&quot;: ask\n    &quot;git diff&quot;: allow\n    &quot;git log*&quot;: allow\n    &quot;grep *&quot;: allow\n  webfetch: deny\n---\n\nOnly analyze code and suggest changes.\n</code></pre>\n<p>You can set permissions for specific bash commands.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;git push&quot;: &quot;ask&quot;,\n          &quot;grep *&quot;: &quot;allow&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>This can take a glob pattern.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;git *&quot;: &quot;ask&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>And you can also use the <code>*</code> wildcard to manage permissions for all commands.\nSince the last matching rule takes precedence, put the <code>*</code> wildcard first and specific rules after.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;*&quot;: &quot;ask&quot;,\n          &quot;git status *&quot;: &quot;allow&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p><a href=\"permissions.html\">Learn more about permissions</a>.</p>\n<hr />\n<h3 id=\"mode\">Mode</h3>\n<p>Control the agent's mode with the <code>mode</code> config. The <code>mode</code> option is used to determine how the agent can be used.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;mode&quot;: &quot;subagent&quot;\n    }\n  }\n}\n</code></pre>\n<p>The <code>mode</code> option can be set to <code>primary</code>, <code>subagent</code>, or <code>all</code>. If no <code>mode</code> is specified, it defaults to <code>all</code>.</p>\n<hr />\n<h3 id=\"hidden\">Hidden</h3>\n<p>Hide a subagent from the <code>@</code> autocomplete menu with <code>hidden: true</code>. Useful for internal subagents that should only be invoked programmatically by other agents via the Task tool.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;internal-helper&quot;: {\n      &quot;mode&quot;: &quot;subagent&quot;,\n      &quot;hidden&quot;: true\n    }\n  }\n}\n</code></pre>\n<p>This only affects user visibility in the autocomplete menu. Hidden agents can still be invoked by the model via the Task tool if permissions allow.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Only applies to <code>mode: subagent</code> agents.</p>\n</div>\n<hr />\n<h3 id=\"task-permissions\">Task permissions</h3>\n<p>Control which subagents an agent can invoke via the Task tool with <code>permission.task</code>. Uses glob patterns for flexible matching.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;orchestrator&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;permission&quot;: {\n        &quot;task&quot;: {\n          &quot;*&quot;: &quot;deny&quot;,\n          &quot;orchestrator-*&quot;: &quot;allow&quot;,\n          &quot;code-reviewer&quot;: &quot;ask&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>When set to <code>deny</code>, the subagent is removed from the Task tool description entirely, so the model won't attempt to invoke it.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Rules are evaluated in order, and the <strong>last matching rule wins</strong>.
