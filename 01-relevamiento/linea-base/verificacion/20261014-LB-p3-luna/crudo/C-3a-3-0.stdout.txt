They allow you to create focused tools with custom prompts, models, and tool access.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Use the plan agent to analyze code and review suggestions without making any code changes.</p>\n</div>\n<p>You can switch between agents during a session or invoke them with the <code>@</code> mention.</p>\n<hr />\n<h2 id=\"types\">Types</h2>\n<p>There are two types of agents in OpenCode; primary agents and subagents.</p>\n<hr />\n<h3 id=\"primary-agents\">Primary agents</h3>\n<p>Primary agents are the main assistants you interact with directly. You can cycle through them using the <strong>Tab</strong> key, or your configured <code>switch_agent</code> keybind. These agents handle your main conversation. Tool access is configured via permissions — for example, Build has all tools enabled while Plan is restricted.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>You can use the <strong>Tab</strong> key to switch between primary agents during a session.</p>\n</div>\n<p>OpenCode comes with two built-in primary agents, <strong>Build</strong> and <strong>Plan</strong>. We'll\nlook at these below.</p>\n<hr />\n<h3 id=\"subagents\">Subagents</h3>\n<p>Subagents are specialized assistants that primary agents can invoke for specific tasks. You can also manually invoke them by <strong>@ mentioning</strong> them in your messages.</p>\n<p>OpenCode comes with three built-in subagents, <strong>General</strong>, <strong>Explore</strong>, and <strong>Scout</strong>. We'll look at this below.</p>\n<hr />\n<h2 id=\"built-in\">Built-in</h2>\n<p>OpenCode comes with two built-in primary agents and three built-in subagents.</p>\n<hr />\n<h3 id=\"use-build\">Use build</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Build is the <strong>default</strong> primary agent with all tools enabled. This is the standard agent for development work where you need full access to file operations and system commands.</p>\n<hr />\n<h3 id=\"use-plan\">Use plan</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>A restricted agent designed for planning and analysis. We use a permission system to give you more control and prevent unintended changes.\nBy default, all of the following are set to <code>ask</code>:</p>\n<ul>\n<li><code>file edits</code>: All writes, patches, and edits</li>\n<li><code>bash</code>: All bash commands</li>\n</ul>\n<p>This agent is useful when you want the LLM to analyze code, suggest changes, or create plans without making any actual modifications to your codebase.</p>\n<hr />\n<h3 id=\"use-general\">Use general</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A general-purpose agent for researching complex questions and executing multi-step tasks. Has full tool access (except todo), so it can make file changes when needed. Use this to run multiple units of work in parallel.</p>\n<hr />\n<h3 id=\"use-explore\">Use explore</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A fast, read-only agent for exploring codebases. Cannot modify files. Use this when you need to quickly find files by patterns, search code for keywords, or answer questions about the codebase.</p>\n<hr />\n<h3 id=\"use-scout\">Use scout</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A read-only agent for external docs and dependency research. Use this when you need to clone a dependency repository into OpenCode's managed cache, inspect library source, or cross-reference local code against upstream implementations without modifying your workspace.</p>\n<hr />\n<h3 id=\"use-compaction\">Use compaction</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that compacts long context into a smaller summary. It runs automatically when needed and is not selectable in the UI.</p>\n<hr />\n<h3 id=\"use-title\">Use title</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that generates short session titles. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h3 id=\"use-summary\">Use summary</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that creates session summaries. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h2 id=\"usage\">Usage</h2>\n<ol>\n<li>\n<p>For primary agents, use the <strong>Tab</strong> key to cycle through them during a session. You can also use your configured <code>switch_agent</code> keybind.</p>\n</li>\n<li>\n<p>Subagents can be invoked:\n   - <strong>Automatically</strong> by primary agents for specialized tasks based on their descriptions.\n   - Manually by <strong>@ mentioning</strong> a subagent in your message. For example.</p>\n<p><code>txt\n @general help me search for this function</code></p>\n</li>\n<li>\n<p><strong>Navigation between sessions</strong>: When subagents create child sessions, use <code>session_child_first</code> (default: <strong>\\<Leader>+Down</strong>) to enter the first child session from the parent.</p>\n</li>\n<li>\n<p>Once you are in a child session, use:\n   - <code>session_child_cycle</code> (default: <strong>Right</strong>) to cycle to the next child session\n   - <code>session_child_cycle_reverse</code> (default: <strong>Left</strong>) to cycle to the previous child session\n   - <code>session_parent</code> (default: <strong>Up</strong>) to return to the parent session</p>\n</li>\n</ol>\n<p>This lets you switch between the main conversation and specialized subagent work.</p>\n<hr />\n<h2 id=\"configure\">Configure</h2>\n<p>You can customize the built-in agents or create your own through configuration. Agents can be configured in two ways:</p>\n<hr />\n<h3 id=\"json\">JSON</h3>\n<p>Configure agents in your <code>opencode.json</code> config file:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n      &quot;prompt&quot;: &quot;{file:./prompts/build.txt}&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;allow&quot;,\n        &quot;bash&quot;: &quot;allow&quot;\n      }\n    },\n    &quot;plan&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;deny&quot;,\n        &quot;bash&quot;: &quot;deny&quot;\n      }\n    },\n    &quot;code-reviewer&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n      &quot;mode&quot;: &quot;subagent&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n      &quot;prompt&quot;: &quot;You are a code reviewer. Focus on security, performance, and maintainability.&quot;,\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;deny&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<hr />\n<h3 id=\"markdown\">Markdown</h3>\n<p>You can also define agents using markdown files. Place them in:</p>\n<ul>\n<li>Global: <code>~/.config/opencode/agents/</code></li>\n<li>Per-project: <code>.opencode/agents/</code></li>\n</ul>\n<pre><code class=\"language-markdown\">---\ndescription: Reviews code for quality and best practices\nmode: subagent\nmodel: anthropic/claude-sonnet-4-20250514\ntemperature: 0.1\npermission:\n  edit: deny\n  bash: deny\n---\n\nYou are in code review mode. Focus on:\n\n- Code quality and best practices\n- Potential bugs and edge cases\n- Performance implications\n- Security considerations\n\nProvide constructive feedback without making direct changes.\n</code></pre>\n<p>The markdown file name becomes the agent name. For example, <code>review.md</code> creates a <code>review</code> agent.</p>\n<hr />\n<h2 id=\"options\">Options</h2>\n<p>Let's look at these configuration options in detail.</p>\n<hr />\n<h3 id=\"description\">Description</h3>\n<p>Use the <code>description</code> option to provide a brief description of what the agent does and when to use it.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n    }\n  }\n}\n</code></pre>\n<p>This is a <strong>required</strong> config option.</p>\n<hr />\n<h3 id=\"temperature\">Temperature</h3>\n<p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code> config.</p>\n<p>Lower values make responses more focused and deterministic, while higher values increase creativity and variability.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;temperature&quot;: 0.1\n    },\n    &quot;creative&quot;: {\n      &quot;temperature&quot;: 0.8\n    }\n  }\n}\n</code></pre>\n<p>Temperature values typically range from 0.0 to 1.0:</p>\n<ul>\n<li><strong>0.0-0.2</strong>: Very focused and deterministic responses, ideal for code analysis and planning</li>\n<li><strong>0.3-0.5</strong>: Balanced responses with some creativity, good for general development tasks</li>\n<li><strong>0.6-1.0</strong>: More creative and varied responses, useful for brainstorming and exploration</li>\n</ul>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;analyze&quot;: {\n      &quot;temperature&quot;: 0.1,\n      &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n    },\n    &quot;build&quot;: {\n      &quot;temperature&quot;: 0.3\n    },\n    &quot;brainstorm&quot;: {\n      &quot;temperature&quot;: 0.7,\n      &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen models.</p>\n<hr />\n<h3 id=\"max-steps\">Max steps</h3>\n<p>Control the maximum number of agentic iterations an agent can perform before being forced to respond with text only. This allows users who wish to control costs to set a limit on agentic actions.</p>\n<p>If this is not set, the agent will continue to iterate until the model chooses to stop or the user interrupts the session.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;quick-thinker&quot;: {\n      &quot;description&quot;: &quot;Fast reasoning with limited iterations&quot;,\n      &quot;prompt&quot;: &quot;You are a quick thinker. Solve problems with minimal steps.&quot;,\n      &quot;steps&quot;: 5\n    }\n  }\n}\n</code></pre>\n<p>When the limit is reached, the agent receives a special system prompt instructing it to respond with a summarization of its work and recommended remaining tasks.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Caution</div>\n<p>The legacy <code>maxSteps</code> field is deprecated. Use <code>steps</code> instead.</p>\n</div>\n<hr />\n<h3 id=\"disable\">Disable</h3>\n<p>Set to <code>true</code> to disable the agent.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;disable&quot;: true\n    }\n  }\n}\n</code></pre>\n<hr />\n<h3 id=\"prompt\">Prompt</h3>\n<p>Specify a custom system prompt file for this agent with the <code>prompt</code> config. The prompt file should contain instructions specific to the agent's purpose.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;prompt&quot;: &quot;{file:./prompts/code-review.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>This path is relative to where the config file is located. So this works for both the global OpenCode config and the project specific config.</p>\n<hr />\n<h3 id=\"model\">Model</h3>\n<p>Use the <code>model</code> config to override the model for this agent. Useful for using different models optimized for different tasks. For example, a faster model for planning, a more capable model for implementation.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>If you don’t specify a model, primary agents use the <a href=\"config.html#models\">model globally configured</a> while subagents will use the model of the primary agent that invoked the subagent.</p>\n</div>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;\n    }\n  }\n}\n</code></pre>\n<p>The model ID in your OpenCode config uses the format <code>provider/model-id</code>. For example, if you're using <a href=\"zen.html\">OpenCode Zen</a>, you would use <code>opencode/gpt-5.1-codex</code> for GPT 5.1 Codex.</p>\n<hr />\n<h3 id=\"tools-deprecated\">Tools (deprecated)</h3>\n<p><code>tools</code> is <strong>deprecated</strong>. Prefer the agent's <a href=\"#permissions\"><code>permission</code></a> field for new configs, updates and more fine-grained control.</p>\n<p>Allows you to control which tools are available in this agent. You can enable or disable specific tools by setting them to <code>true</code> or <code>false</code>. In an agent's <code>tools</code> config, <code>true</code> is equivalent to <code>{\"*\": \"allow\"}</code> permission and <code>false</code> is equivalent to <code>{\"*\": \"deny\"}</code> permission.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;tools&quot;: {\n    &quot;write&quot;: true,\n    &quot;bash&quot;: true\n  },\n  &quot;agent&quot;: {\n    &quot;plan&quot;: {\n      &quot;tools&quot;: {\n        &quot;write&quot;: false,\n        &quot;bash&quot;: false\n      }\n    }\n  }\n}\n</code></pre>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>The agent-specific config overrides the global config.</p>\n</div>\n<p>You can also use wildcards in legacy <code>tools</code> entries to control multiple tools at once. For example, to disable all tools from an MCP server:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;readonly&quot;: {\n      &quot;tools&quot;: {\n        &quot;mymcp_*&quot;: false,\n        &quot;write&quot;: false,\n        &quot;edit&quot;: false\n      }\n    }\n  }\n}\n</code></pre>\n<p><a href=\"tools.html\">Learn more about tools</a>.</p>\n<hr />\n<h3 id=\"permissions\">Permissions</h3>\n<p>You can configure permissions to manage what actions an agent can take. Each permission key can be set to:</p>\n<ul>\n<li><code>\"ask\"</code> — Prompt for approval before running the tool</li>\n<li><code>\"allow\"</code> — Allow all operations without approval</li>\n<li><code>\"deny\"</code> — Disable the tool</li>\n</ul>\n<p>The available permission keys are:</p>\n<table>\n<thead>\n<tr>\n<th>Key</th>\n<th>Tools it gates</th>\n</tr>\n</thead>\n<tbody>\n<tr>\n<td><code>read</code></td>\n<td><code>read</code></td>\n</tr>\n<tr>\n<td><code>edit</code></td>\n<td><code>write</code>, <code>edit</code>, <code>apply_patch</code></td>\n</tr>\n<tr>\n<td><code>glob</code></td>\n<td><code>glob</code></td>\n</tr>\n<tr>\n<td><code>grep</code></td>\n<td><code>grep</code></td>\n</tr>\n<tr>\n<td><code>list</code></td>\n<td><code>list</code></td>\n</tr>\n<tr>\n<td><code>bash</code></td>\n<td><code>bash</code></td>\n</tr>\n<tr>\n<td><code>task</code></td>\n<td><code>task</code></td>\n</tr>\n<tr>\n<td><code>external_directory</code></td>\n<td>Any tool that reads or writes files outside the project worktree</td>\n</tr>\n<tr>\n<td><code>todowrite</code></td>\n<td><code>todowrite</code>, <code>todoread</code></td>\n</tr>\n<tr>\n<td><code>webfetch</code></td>\n<td><code>webfetch</code></td>\n</tr>\n<tr>\n<td><code>websearch</code></td>\n<td><code>websearch</code></td>\n</tr>\n<tr>\n<td><code>lsp</code></td>\n<td><code>lsp</code></td>\n</tr>\n<tr>\n<td><code>skill</code></td>\n<td><code>skill</code></td>\n</tr>\n<tr>\n<td><code>question</code></td>\n<td><code>question</code></td>\n</tr>\n<tr>\n<td><code>doom_loop</code></td>\n<td>Recovery prompts when an agent appears stuck</td>\n</tr>\n</tbody>\n</table>\n<p><code>read</code>, <code>edit</code>, <code>glob</code>, <code>grep</code>, <code>list</code>, <code>bash</code>, <code>task</code>, <code>external_directory</code>, <code>lsp</code>, and <code>skill</code> accept either a shorthand action (<code>\"allow\" | \"ask\" | \"deny\"</code>) or an object of glob/pattern → action for fine-grained control. The remaining keys accept the shorthand action only.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Permission keys are matched as wildcard patterns against the underlying tool name, so the same syntax works for built-ins, custom tools, and MCP tools — for example <code>\"mymcp_*\": \"deny\"</code> denies every tool from an MCP server, and <code>\"mymcp_search\": \"ask\"</code> targets a single one.</p>\n</div>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;edit&quot;: &quot;deny&quot;\n  }\n}\n</code></pre>\n<p>You can override these permissions per agent.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;edit&quot;: &quot;deny&quot;\n  },\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;edit&quot;: &quot;ask&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<p>You can also set permissions in Markdown agents.</p>\n<pre><code class=\"language-markdown\">---\ndescription: Code review without edits\nmode: subagent\npermission:\n  edit: deny\n  bash:\n    &quot;*&quot;: ask\n    &quot;git diff&quot;: allow\n    &quot;git log*&quot;: allow\n    &quot;grep *&quot;: allow\n  webfetch: deny\n---\n\nOnly analyze code and suggest changes.\n</code></pre>\n<p>You can set permissions for specific bash commands.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;git push&quot;: &quot;ask&quot;,\n          &quot;grep *&quot;: &quot;allow&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>This can take a glob pattern.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;git *&quot;: &quot;ask&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>And you can also use the <code>*</code> wildcard to manage permissions for all commands.\nSince the last matching rule takes precedence, put the <code>*</code> wildcard first and specific rules after.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;*&quot;: &quot;ask&quot;,\n          &quot;git status *&quot;: &quot;allow&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p><a href=\"permissions.html\">Learn more about permissions</a>.</p>\n<hr />\n<h3 id=\"mode\">Mode</h3>\n<p>Control the agent's mode with the <code>mode</code> config. The <code>mode</code> option is used to determine how the agent can be used.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;mode&quot;: &quot;subagent&quot;\n    }\n  }\n}\n</code></pre>\n<p>The <code>mode</code> option can be set to <code>primary</code>, <code>subagent</code>, or <code>all</code>. If no <code>mode</code> is specified, it defaults to <code>all</code>.</p>\n<hr />\n<h3 id=\"hidden\">Hidden</h3>\n<p>Hide a subagent from the <code>@</code> autocomplete menu with <code>hidden: true</code>. Useful for internal subagents that should only be invoked programmatically by other agents via the Task tool.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;internal-helper&quot;: {\n      &quot;mode&quot;: &quot;subagent&quot;,\n      &quot;hidden&quot;: true\n    }\n  }\n}\n</code></pre>\n<p>This only affects user visibility in the autocomplete menu. Hidden agents can still be invoked by the model via the Task tool if permissions allow.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Only applies to <code>mode: subagent</code> agents.</p>\n</div>\n<hr />\n<h3 id=\"task-permissions\">Task permissions</h3>\n<p>Control which subagents an agent can invoke via the Task tool with <code>permission.task</code>. Uses glob patterns for flexible matching.</p>\n<pre><code class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;orchestrator&quot;: {\n      &quot;mode&quot;: &quot;primary&quot;,\n      &quot;permission&quot;: {\n        &quot;task&quot;: {\n          &quot;*&quot;: &quot;deny&quot;,\n          &quot;orchestrator-*&quot;: &quot;allow&quot;,\n          &quot;code-reviewer&quot;: &quot;ask&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>When set to <code>deny</code>, the subagent is removed from the Task tool description entirely, so the model won't attempt to invoke it.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Rules are evaluated in order, and the <strong>last matching rule wins</strong>.
