&quot;port&quot;: 4096,\n80:   },\n81: }\n82: </code></pre>\n83: <hr />\n84: <h2 id=\"locations\">Locations</h2>\n85: <p>You can place your config in a couple of different locations and they have a\n86: different order of precedence.</p>\n87: <div class=\"aside\">\n88: <div class=\"aside-t\">Note</div>\n89: <p>Configuration files are <strong>merged together</strong>, not replaced.</p>\n90: </div>\n91: <p>Configuration files are merged together, not replaced. Settings from the following config locations are combined. Later configs override earlier ones only for conflicting keys. Non-conflicting settings from all configs are preserved.</p>\n92: <p>For example, if your global config sets <code>autoupdate: true</code> and your project config sets <code>model: \"anthropic/claude-sonnet-4-5\"</code>, the final configuration will include both settings.</p>\n93: <hr />\n94: <h3 id=\"precedence-order\">Precedence order</h3>\n95: <p>Config sources are loaded in this order (later sources override earlier ones):</p>\n96: <ol>\n97: <li><strong>Remote config</strong> (from <code>.well-known/opencode</code>) - organizational defaults</li>\n98: <li><strong>Global config</strong> (<code>~/.config/opencode/opencode.json</code>) - user preferences</li>\n99: <li><strong>Custom config</strong> (<code>OPENCODE_CONFIG</code> env var) - custom overrides</li>\n100: <li><strong>Project config</strong> (<code>opencode.json</code> in project) - project-specific settings</li>\n101: <li><strong><code>.opencode</code> directories</strong> - agents, commands, plugins</li>\n102: <li><strong>Inline config</strong> (<code>OPENCODE_CONFIG_CONTENT</code> env var) - runtime overrides</li>\n103: <li><strong>Managed config files</strong> (<code>/Library/Application Support/opencode/</code> on macOS) - admin-controlled</li>\n104: <li><strong>macOS managed preferences</strong> (<code>.mobileconfig</code> via MDM) - highest priority, not user-overridable</li>\n105: </ol>\n106: <p>This means project configs can override global defaults, and global configs can override remote organizational defaults. Managed settings override everything.</p>\n107: <div class=\"aside\">\n108: <div class=\"aside-t\">Note</div>\n109: <p>The <code>.opencode</code> and <code>~/.config/opencode</code> directories use <strong>plural names</strong> for subdirectories: <code>agents/</code>, <code>commands/</code>, <code>modes/</code>, <code>plugins/</code>, <code>skills/</code>, <code>tools/</code>, and <code>themes/</code>. Singular names (e.g., <code>agent/</code>) are also supported for backwards compatibility.</p>\n110: </div>\n111: <hr />\n112: <h3 id=\"remote\">Remote</h3>\n113: <p>Organizations can provide default configuration via the <code>.well-known/opencode</code> endpoint. This is fetched automatically when you authenticate with a provider that supports it.</p>\n114: <p>Remote config is loaded first, serving as the base layer. All other config sources (global, project) can override these defaults.</p>\n115: <p>For example, if your organization provides MCP servers that are disabled by default:</p>\n116: <pre><code class=\"language-json\">{\n117:   &quot;mcp&quot;: {\n118:     &quot;jira&quot;: {\n119:       &quot;type&quot;: &quot;remote&quot;,\n120:       &quot;url&quot;: &quot;https://jira.example.com/mcp&quot;,\n121:       &quot;enabled&quot;: false\n122:     }\n123:   }\n124: }\n125: </code></pre>\n126: <p>You can enable specific servers in your local config:</p>\n127: <pre><code class=\"language-json\">{\n128:   &quot;mcp&quot;: {\n129:     &quot;jira&quot;: {\n130:       &quot;type&quot;: &quot;remote&quot;,\n131:       &quot;url&quot;: &quot;https://jira.example.com/mcp&quot;,\n132:       &quot;enabled&quot;: true\n133:     }\n134:   }\n135: }\n136: </code></pre>\n137: <hr />\n138: <h3 id=\"global\">Global</h3>\n139: <p>Place your global OpenCode config in <code>~/.config/opencode/opencode.json</code>. Use global config for user-wide server/runtime preferences like providers, models, and permissions.</p>\n140: <p>For TUI-specific settings, use <code>~/.config/opencode/tui.json</code>.</p>\n141: <p>Global config overrides remote organizational defaults.</p>\n142: <hr />\n143: <h3 id=\"per-project\">Per project</h3>\n144: <p>Add <code>opencode.json</code> in your project root. Project config has the highest precedence among standard config files - it overrides both global and remote configs.</p>\n145: <p>For project-specific TUI settings, add <code>tui.json</code> alongside it.</p>\n146: <div class=\"aside\">\n147: <div class=\"aside-t\">Tip</div>\n148: <p>Place project specific config in the root of your project.</p>\n149: </div>\n150: <p>When OpenCode starts up, it first looks for a config file in the current directory, then traverses up to the nearest Git directory.</p>\n151: <p>This is also safe to be checked into Git and uses the same schema as the global one.</p>\n152: <hr />\n153: <h3 id=\"custom-path\">Custom path</h3>\n154: <p>Specify a custom config file path using the <code>OPENCODE_CONFIG</code> environment variable.</p>\n155: <pre><code class=\"language-bash\">export OPENCODE_CONFIG=/path/to/my/custom-config.json\n156: opencode run &quot;Hello world&quot;\n157: </code></pre>\n158: <p>Custom config is loaded between global and project configs in the precedence order.</p>\n159: <hr />\n160: <h3 id=\"custom-directory\">Custom directory</h3>\n161: <p>Specify a custom config directory using the <code>OPENCODE_CONFIG_DIR</code>\n162: environment variable. This directory will be searched for agents, commands,\n163: modes, and plugins just like the standard <code>.opencode</code> directory, and should\n164: follow the same structure.</p>\n165: <pre><code class=\"language-bash\">export OPENCODE_CONFIG_DIR=/path/to/my/config-directory\n166: opencode run &quot;Hello world&quot;\n167: </code></pre>\n168: <p>The custom directory is loaded after the global config and <code>.opencode</code> directories, so it <strong>can override</strong> their settings.</p>\n169: <hr />\n170: <h3 id=\"managed-settings\">Managed settings</h3>\n171: <p>Organizations can enforce configuration that users cannot override. Managed settings are loaded at the highest priority tier.</p>\n172: <h4 id=\"file-based\">File-based</h4>\n173: <p>Drop an <code>opencode.json</code> or <code>opencode.jsonc</code> file in the system managed config directory:</p>\n174: <table>\n175: <thead>\n176: <tr>\n177: <th>Platform</th>\n178: <th>Path</th>\n179: </tr>\n180: </thead>\n181: <tbody>\n182: <tr>\n183: <td>macOS</td>\n184: <td><code>/Library/Application Support/opencode/</code></td>\n185: </tr>\n186: <tr>\n187: <td>Linux</td>\n188: <td><code>/etc/opencode/</code></td>\n189: </tr>\n190: <tr>\n191: <td>Windows</td>\n192: <td><code>%ProgramData%\\opencode</code></td>\n193: </tr>\n194: </tbody>\n195: </table>\n196: <p>These directories require admin/root access to write, so users cannot modify them.</p>\n197: <h4 id=\"macos-managed-preferences\">macOS managed preferences</h4>\n198: <p>On macOS, OpenCode reads managed preferences from the <code>ai.opencode.managed</code> preference domain. When <code>mdns</code> is enabled and no hostname is set, defaults to <code>0.0.0.0</code>.</li>\n316: <li><code>mdns</code> - Enable mDNS service discovery. This allows other devices on the network to discover your OpenCode server.</li>\n317: <li><code>mdnsDomain</code> - Custom domain name for mDNS service. Defaults to <code>opencode.local</code>. Useful for running multiple instances on the same network.</li>\n318: <li><code>cors</code> - Additional origins to allow for CORS when using the HTTP server from a browser-based client. Values must be full origins (scheme + host + optional port), eg <code>https://app.example.com</code>.</li>\n319: </ul>\n320: <p><a href=\"server.html\">Learn more about the server here</a>.</p>\n321: <hr />\n322: <h3 id=\"shell\">Shell</h3>\n323: <p>You can configure the shell used for the interactive terminal using the <code>shell</code> option. Compatible shells are also used for agent tool calls.</p>\n324: <pre><code class=\"language-json\">{\n325:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n326:   &quot;shell&quot;: &quot;pwsh&quot;\n327: }\n328: </code></pre>\n329: <p>If not specified, OpenCode will automatically discover and use a sensible default based on your operating system (e.g. <code>pwsh</code> or <code>cmd.exe</code> on Windows, <code>/bin/zsh</code> or <code>/bin/bash</code> on macOS/Linux). You can provide an absolute path or a short name.</p>\n330: <hr />\n331: <h3 id=\"tools\">Tools</h3>\n332: <p>You can manage the tools an LLM can use through the <code>tools</code> option.</p>\n333: <pre><code class=\"language-json\">{\n334:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n335:   &quot;tools&quot;: {\n336:     &quot;write&quot;: false,\n337:     &quot;bash&quot;: false\n338:   }\n339: }\n340: </code></pre>\n341: <p><a href=\"tools.html\">Learn more about tools here</a>.</p>\n342: <hr />\n343: <h3 id=\"models\">Models</h3>\n344: <p>You can configure the providers and models you want to use in your OpenCode config through the <code>provider</code>, <code>model</code> and <code>small_model</code> options.</p>\n345: <pre><code class=\"language-json\">{\n346:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n347:   &quot;provider&quot;: {},\n348:   &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n349:   &quot;small_model&quot;: &quot;anthropic/claude-haiku-4-5&quot;\n350: }\n351: </code></pre>\n352: <p>The <code>small_model</code> option configures a separate model for lightweight tasks like title generation. By default, OpenCode tries to use a cheaper model if one is available from your provider, otherwise it falls back to your main model.</p>\n353: <p>Provider options can include <code>timeout</code>, <code>chunkTimeout</code>, and <code>setCacheKey</code>:</p>\n354: <pre><code class=\"language-json\">{\n355:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n356:   &quot;provider&quot;: {\n357:     &quot;anthropic&quot;: {\n358:       &quot;options&quot;: {\n359:         &quot;timeout&quot;: 600000,\n360:         &quot;chunkTimeout&quot;: 30000,\n361:         &quot;setCacheKey&quot;: true\n362:       }\n363:     }\n364:   }\n365: }\n366: </code></pre>\n367: <ul>\n368: <li><code>timeout</code> - Request timeout in milliseconds (default: 300000). Set to <code>false</code> to disable.</li>\n369: <li><code>chunkTimeout</code> - Timeout in milliseconds between streamed response chunks. If no chunk arrives in time, the request is aborted.</li>\n370: <li><code>setCacheKey</code> - Ensure a cache key is always set for designated provider.</li>\n371: </ul>\n372: <p>You can also configure <a href=\"models.html#local\">local models</a>. <a href=\"models.html\">Learn more</a>.</p>\n373: <hr />\n374: <h3 id=\"policies\">Policies</h3>\n375: <p>Use the <code>experimental.policies</code> option to allow or deny OpenCode actions on configured resources. By default, images are resized when they exceed <code>2000x2000</code> pixels or <code>5242880</code> base64 bytes.</p>\n393: <p>Configure image attachment limits with the <code>attachment.image</code> option:</p>\n394: <pre><code class=\"language-json\">{\n395:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n396:   &quot;attachment&quot;: {\n397:     &quot;image&quot;: {\n398:       &quot;auto_resize&quot;: true,\n399:       &quot;max_width&quot;: 2000,\n400:       &quot;max_height&quot;: 2000,\n401:       &quot;max_base64_bytes&quot;: 5242880\n402:     }\n403:   }\n404: }\n405: </code></pre>\n406: <ul>\n407: <li><code>auto_resize</code> - Resize images that exceed the configured limits before provider requests. This is the base64 payload size, not the original file size.</li>\n411: </ul>\n412: <p>If an image still cannot fit after resizing, OpenCode omits oversized tool-result images or fails oversized user-provided images with an image size error.</p>\n413: <hr />\n414: <h4 id=\"provider-specific-options\">Provider-Specific Options</h4>\n415: <p>Some providers support additional configuration options beyond the generic <code>timeout</code> and <code>apiKey</code> settings.</p>\n416: <h5 id=\"amazon-bedrock\">Amazon Bedrock</h5>\n417: <p>Amazon Bedrock supports AWS-specific configuration:</p>\n418: <pre><code class=\"language-json\">{\n419:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n420:   &quot;provider&quot;: {\n421:     &quot;amazon-bedrock&quot;: {\n422:       &quot;options&quot;: {\n423:         &quot;region&quot;: &quot;us-east-1&quot;,\n424:         &quot;profile&quot;: &quot;my-aws-profile&quot;,\n425:         &quot;endpoint&quot;: &quot;https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com&quot;\n426:       }\n427:     }\n428:   }\n429: }\n430: </code></pre>\n431: <ul>\n432: <li><code>region</code> - AWS region for Bedrock (defaults to <code>AWS_REGION</code> env var or <code>us-east-1</code>)</li>\n433: <li><code>profile</code> - AWS named profile from <code>~/.aws/credentials</code> (defaults to <code>AWS_PROFILE</code> env var)</li>\n434: <li><code>endpoint</code> - Custom endpoint URL for VPC endpoints. This is an alias for the generic <code>baseURL</code> option using AWS-specific terminology. If both are specified, <code>endpoint</code> takes precedence.</li>\n435: </ul>\n436: <div class=\"aside\">\n437: <div class=\"aside-t\">Note</div>\n438: <p>Bearer tokens (<code>AWS_BEARER_TOKEN_BEDROCK</code> or <code>/connect</code>) take precedence over profile-based authentication. See <a href=\"providers.html#authentication-precedence\">authentication precedence</a> for details.</p>\n439: </div>\n440: <p><a href=\"providers.html#amazon-bedrock\">Learn more about Amazon Bedrock configuration</a>.</p>\n441: <hr />\n442: <h3 id=\"themes\">Themes</h3>\n443: <p>Set your UI theme in <code>tui.json</code>.</p>\n444: <pre><code class=\"language-json\">{\n445:   &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n446:   &quot;theme&quot;: &quot;tokyonight&quot;\n447: }\n448: </code></pre>\n449: <p><a href=\"themes.html\">Learn more here</a>.</p>\n450: <hr />\n451: <h3 id=\"agents\">Agents</h3>\n452: <p>You can configure specialized agents for specific tasks through the <code>agent</code> option.</p>\n453: <pre><code class=\"language-jsonc\">{\n454:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n455:   &quot;agent&quot;: {\n456:     &quot;code-reviewer&quot;: {\n457:       &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n458:       &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n459:       &quot;prompt&quot;: &quot;You are a code reviewer. class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Configuration files are <strong>merged together</strong>, not replaced.</p>\n</div>\n<p>Configuration files are merged together, not replaced. Settings from the following config locations are combined. Later configs override earlier ones only for conflicting keys. Non-conflicting settings from all configs are preserved.</p>\n<p>For example, if your global config sets <code>autoupdate: true</code> and your project config sets <code>model: \"anthropic/claude-sonnet-4-5\"</code>, the final configuration will include both settings.</p>\n<hr />\n<h3 id=\"precedence-order\">Precedence order</h3>\n<p>Config sources are loaded in this order (later sources override earlier ones):</p>\n<ol>\n<li><strong>Remote config</strong> (from <code>.well-known/opencode</code>) - organizational defaults</li>\n<li><strong>Global config</strong> (<code>~/.config/opencode/opencode.json</code>) - user preferences</li>\n<li><strong>Custom config</strong> (<code>OPENCODE_CONFIG</code> env var) - custom overrides</li>\n<li><strong>Project config</strong> (<code>opencode.json</code> in project) - project-specific settings</li>\n<li><strong><code>.opencode</code> directories</strong> - agents, commands, plugins</li>\n<li><strong>Inline config</strong> (<code>OPENCODE_CONFIG_CONTENT</code> env var) - runtime overrides</li>\n<li><strong>Managed config files</strong> (<code>/Library/Application Support/opencode/</code> on macOS) - admin-controlled</li>\n<li><strong>macOS managed preferences</strong> (<code>.mobileconfig</code> via MDM) - highest priority, not user-overridable</li>\n</ol>\n<p>This means project configs can override global defaults, and global configs can override remote organizational defaults. Managed settings override everything.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>The <code>.opencode</code> and <code>~/.config/opencode</code> directories use <strong>plural names</strong> for subdirectories: <code>agents/</code>, <code>commands/</code>, <code>modes/</code>, <code>plugins/</code>, <code>skills/</code>, <code>tools/</code>, and <code>themes/</code>. Singular names (e.g., <code>agent/</code>) are also supported for backwards compatibility.</p>\n</div>\n<hr />\n<h3 id=\"remote\">Remote</h3>\n<p>Organizations can provide default configuration via the <code>.well-known/opencode</code> endpoint. This is fetched automatically when you authenticate with a provider that supports it.</p>\n<p>Remote config is loaded first, serving as the base layer. All other config sources (global, project) can override these defaults.</p>\n<p>For example, if your organization provides MCP servers that are disabled by default:</p>\n<pre><code class=\"language-json\">{\n  &quot;mcp&quot;: {\n    &quot;jira&quot;: {\n      &quot;type&quot;: &quot;remote&quot;,\n      &quot;url&quot;: &quot;https://jira.example.com/mcp&quot;,\n      &quot;enabled&quot;: false\n    }\n  }\n}\n</code></pre>\n<p>You can enable specific servers in your local config:</p>\n<pre><code class=\"language-json\">{\n  &quot;mcp&quot;: {\n    &quot;jira&quot;: {\n      &quot;type&quot;: &quot;remote&quot;,\n      &quot;url&quot;: &quot;https://jira.example.com/mcp&quot;,\n      &quot;enabled&quot;: true\n    }\n  }\n}\n</code></pre>\n<hr />\n<h3 id=\"global\">Global</h3>\n<p>Place your global OpenCode config in <code>~/.config/opencode/opencode.json</code>. Use global config for user-wide server/runtime preferences like providers, models, and permissions.</p>\n<p>For TUI-specific settings, use <code>~/.config/opencode/tui.json</code>.</p>\n<p>Global config overrides remote organizational defaults.</p>\n<hr />\n<h3 id=\"per-project\">Per project</h3>\n<p>Add <code>opencode.json</code> in your project root. Project config has the highest precedence among standard config files - it overrides both global and remote configs.</p>\n<p>For project-specific TUI settings, add <code>tui.json</code> alongside it.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Place project specific config in the root of your project.</p>\n</div>\n<p>When OpenCode starts up, it first looks for a config file in the current directory, then traverses up to the nearest Git directory.</p>\n<p>This is also safe to be checked into Git and uses the same schema as the global one.</p>\n<hr />\n<h3 id=\"custom-path\">Custom path</h3>\n<p>Specify a custom config file path using the <code>OPENCODE_CONFIG</code> environment variable.</p>\n<pre><code class=\"language-bash\">export OPENCODE_CONFIG=/path/to/my/custom-config.json\nopencode run &quot;Hello world&quot;\n</code></pre>\n<p>Custom config is loaded between global and project configs in the precedence order.</p>\n<hr />\n<h3 id=\"custom-directory\">Custom directory</h3>\n<p>Specify a custom config directory using the <code>OPENCODE_CONFIG_DIR</code>\nenvironment variable. This directory will be searched for agents, commands,\nmodes, and plugins just like the standard <code>.opencode</code> directory, and should\nfollow the same structure.</p>\n<pre><code class=\"language-bash\">export OPENCODE_CONFIG_DIR=/path/to/my/config-directory\nopencode run &quot;Hello world&quot;\n</code></pre>\n<p>The custom directory is loaded after the global config and <code>.opencode</code> directories, so it <strong>can override</strong> their settings.</p>\n<hr />\n<h3 id=\"managed-settings\">Managed settings</h3>\n<p>Organizations can enforce configuration that users cannot override. Managed settings are loaded at the highest priority tier.</p>\n<h4 id=\"file-based\">File-based</h4>\n<p>Drop an <code>opencode.json</code> or <code>opencode.jsonc</code> file in the system managed config directory:</p>\n<table>\n<thead>\n<tr>\n<th>Platform</th>\n<th>Path</th>\n</tr>\n</thead>\n<tbody>\n<tr>\n<td>macOS</td>\n<td><code>/Library/Application Support/opencode/</code></td>\n</tr>\n<tr>\n<td>Linux</td>\n<td><code>/etc/opencode/</code></td>\n</tr>\n<tr>\n<td>Windows</td>\n<td><code>%ProgramData%\\opencode</code></td>\n</tr>\n</tbody>\n</table>\n<p>These directories require admin/root access to write, so users cannot modify them.</p>\n<h4 id=\"macos-managed-preferences\">macOS managed preferences</h4>\n<p>On macOS, OpenCode reads managed preferences from the <code>ai.opencode.managed</code> preference domain. Deploy a <code>.mobileconfig</code> via MDM (Jamf, Kandji, FleetDM) and the settings are enforced automatically.</p>\n<p>OpenCode checks these paths:</p>\n<ol>\n<li><code>/Library/Managed Preferences/&lt;user&gt;/ai.opencode.managed.plist</code></li>\n<li><code>/Library/Managed Preferences/ai.opencode.managed.plist</code></li>\n</ol>\n<p>The plist keys map directly to <code>opencode.json</code> fields. MDM metadata keys (<code>PayloadUUID</code>, <code>PayloadType</code>, etc.) are stripped automatically.</p>\n<p><strong>Creating a <code>.mobileconfig</code></strong></p>\n<p>Use the <code>ai.opencode.managed</code> PayloadType. The OpenCode config keys go directly in the payload dict:</p>\n<pre><code class=\"language-xml\">&lt;?xml version=&quot;1.0&quot; encoding=&quot;UTF-8&quot;?&gt;\n&lt;!DOCTYPE plist PUBLIC &quot;-//Apple//DTD PLIST 1.0//EN&quot;\n  &quot;http://www.apple.com/DTDs/PropertyList-1.0.dtd&quot;&gt;\n&lt;plist version=&quot;1.0&quot;&gt;\n&lt;dict&gt;\n  &lt;key&gt;PayloadContent&lt;/key&gt;\n  &lt;array&gt;\n    &lt;dict&gt;\n      &lt;key&gt;PayloadType&lt;/key&gt;\n      &lt;string&gt;ai.opencode.managed&lt;/string&gt;\n      &lt;key&gt;PayloadIdentifier&lt;/key&gt;\n      &lt;string&gt;com.example.opencode.config&lt;/string&gt;\n      &lt;key&gt;PayloadUUID&lt;/key&gt;\n      &lt;string&gt;GENERATE-YOUR-OWN-UUID&lt;/string&gt;\n      &lt;key&gt;PayloadVersion&lt;/key&gt;\n      &lt;integer&gt;1&lt;/integer&gt;\n      &lt;key&gt;share&lt;/key&gt;\n      &lt;string&gt;disabled&lt;/string&gt;\n      &lt;key&gt;server&lt;/key&gt;\n      &lt;dict&gt;\n        &lt;key&gt;hostname&lt;/key&gt;\n        &lt;string&gt;127.0.0.1&lt;/string&gt;\n      &lt;/dict&gt;\n      &lt;key&gt;permission&lt;/key&gt;\n      &lt;dict&gt;\n        &lt;key&gt;*&lt;/key&gt;\n        &lt;string&gt;ask&lt;/string&gt;\n        &lt;key&gt;bash&lt;/key&gt;\n        &lt;dict&gt;\n          &lt;key&gt;*&lt;/key&gt;\n          &lt;string&gt;ask&lt;/string&gt;\n          &lt;key&gt;rm -rf *&lt;/key&gt;\n          &lt;string&gt;deny&lt;/string&gt;\n        &lt;/dict&gt;\n      &lt;/dict&gt;\n    &lt;/dict&gt;\n  &lt;/array&gt;\n  &lt;key&gt;PayloadType&lt;/key&gt;\n  &lt;string&gt;Configuration&lt;/string&gt;\n  &lt;key&gt;PayloadIdentifier&lt;/key&gt;\n  &lt;string&gt;com.example.opencode&lt;/string&gt;\n  &lt;key&gt;PayloadUUID&lt;/key&gt;\n  &lt;string&gt;GENERATE-YOUR-OWN-UUID&lt;/string&gt;\n  &lt;key&gt;PayloadVersion&lt;/key&gt;\n  &lt;integer&gt;1&lt;/integer&gt;\n&lt;/dict&gt;\n&lt;/plist&gt;\n</code></pre>\n<p>Generate unique UUIDs with <code>uuidgen</code>. Customize the settings to match your organization's requirements.</p>\n<p><strong>Deploying via MDM</strong></p>\n<ul>\n<li><strong>Jamf Pro:</strong> Computers &gt; Configuration Profiles &gt; Upload &gt; scope to target devices or smart groups</li>\n<li><strong>FleetDM:</strong> Add the <code>.mobileconfig</code> to your gitops repo under <code>mdm.macos_settings.custom_settings</code> and run <code>fleetctl apply</code></li>\n</ul>\n<p><strong>Verifying on a device</strong></p>\n<p>Double-click the <code>.mobileconfig</code> to install locally for testing (shows in System Settings &gt; Privacy &amp; Security &gt; Profiles), then run:</p>\n<pre><code class=\"language-bash\">opencode debug config\n</code></pre>\n<p>All managed preference keys appear in the resolved config and cannot be overridden by user or project configuration.</p>\n<hr />\n<h2 id=\"schema\">Schema</h2>\n<p>The server/runtime config schema is defined in <a href=\"https://opencode.ai/config.json\"><strong><code>opencode.ai/config.json</code></strong></a>.</p>\n<p>TUI config uses <a href=\"https://opencode.ai/tui.json\"><strong><code>opencode.ai/tui.json</code></strong></a>.</p>\n<p>Your editor should be able to validate and autocomplete based on the schema.</p>\n<hr />\n<h3 id=\"tui\">TUI</h3>\n<p>Use a dedicated <code>tui.json</code> (or <code>tui.jsonc</code>) file for TUI-specific settings.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n  &quot;scroll_speed&quot;: 3,\n  &quot;scroll_acceleration&quot;: {\n    &quot;enabled&quot;: true\n  },\n  &quot;diff_style&quot;: &quot;auto&quot;,\n  &quot;cursor&quot;: {\n    &quot;style&quot;: &quot;block&quot;,\n    &quot;blinking&quot;: true\n  },\n  &quot;mouse&quot;: true,\n  &quot;attention&quot;: {\n    &quot;enabled&quot;: true,\n    &quot;notifications&quot;: true,\n    &quot;sound&quot;: true,\n    &quot;volume&quot;: 0.4\n  }\n}\n</code></pre>\n<p>Use <code>OPENCODE_TUI_CONFIG</code> to point to a custom TUI config file.</p>\n<p>When <code>cursor.style</code> is <code>\"default\"</code>, the terminal default cursor is restored, so <code>cursor.blinking</code> has no effect.</p>\n<p>Set <code>attention.enabled</code> to turn on TUI desktop notifications and sounds. See <a href=\"tui.html#attention\">TUI attention</a>.</p>\n<p>Legacy <code>theme</code>, <code>keybinds</code>, and <code>tui</code> keys in <code>opencode.json</code> are deprecated and automatically migrated when possible.</p>\n<hr />\n<h3 id=\"server\">Server</h3>\n<p>You can configure server settings for the <code>opencode serve</code> and <code>opencode web</code> commands through the <code>server</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;server&quot;: {\n    &quot;port&quot;: 4096,\n    &quot;hostname&quot;: &quot;0.0.0.0&quot;,\n    &quot;mdns&quot;: true,\n    &quot;mdnsDomain&quot;: &quot;myproject.local&quot;,\n    &quot;cors&quot;: [&quot;http://localhost:5173&quot;]\n  }\n}\n</code></pre>\n<p>Available options:</p>\n<ul>\n<li><code>port</code> - Port to listen on.</li>\n<li><code>hostname</code> - Hostname to listen on. When <code>mdns</code> is enabled and no hostname is set, defaults to <code>0.0.0.0</code>.</li>\n<li><code>mdns</code> - Enable mDNS service discovery. This allows other devices on the network to discover your OpenCode server.</li>\n<li><code>mdnsDomain</code> - Custom domain name for mDNS service. Defaults to <code>opencode.local</code>. Useful for running multiple instances on the same network.</li>\n<li><code>cors</code> - Additional origins to allow for CORS when using the HTTP server from a browser-based client. Values must be full origins (scheme + host + optional port), eg <code>https://app.example.com</code>.</li>\n</ul>\n<p><a href=\"server.html\">Learn more about the server here</a>.</p>\n<hr />\n<h3 id=\"shell\">Shell</h3>\n<p>You can configure the shell used for the interactive terminal using the <code>shell</code> option. Compatible shells are also used for agent tool calls.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;shell&quot;: &quot;pwsh&quot;\n}\n</code></pre>\n<p>If not specified, OpenCode will automatically discover and use a sensible default based on your operating system (e.g. <code>pwsh</code> or <code>cmd.exe</code> on Windows, <code>/bin/zsh</code> or <code>/bin/bash</code> on macOS/Linux). You can provide an absolute path or a short name.</p>\n<hr />\n<h3 id=\"tools\">Tools</h3>\n<p>You can manage the tools an LLM can use through the <code>tools</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;tools&quot;: {\n    &quot;write&quot;: false,\n    &quot;bash&quot;: false\n  }\n}\n</code></pre>\n<p><a href=\"tools.html\">Learn more about tools here</a>.</p>\n<hr />\n<h3 id=\"models\">Models</h3>\n<p>You can configure the providers and models you want to use in your OpenCode config through the <code>provider</code>, <code>model</code> and <code>small_model</code> options.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {},\n  &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n  &quot;small_model&quot;: &quot;anthropic/claude-haiku-4-5&quot;\n}\n</code></pre>\n<p>The <code>small_model</code> option configures a separate model for lightweight tasks like title generation. By default, OpenCode tries to use a cheaper model if one is available from your provider, otherwise it falls back to your main model.</p>\n<p>Provider options can include <code>timeout</code>, <code>chunkTimeout</code>, and <code>setCacheKey</code>:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {\n    &quot;anthropic&quot;: {\n      &quot;options&quot;: {\n        &quot;timeout&quot;: 600000,\n        &quot;chunkTimeout&quot;: 30000,\n        &quot;setCacheKey&quot;: true\n      }\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>timeout</code> - Request timeout in milliseconds (default: 300000). Set to <code>false</code> to disable.</li>\n<li><code>chunkTimeout</code> - Timeout in milliseconds between streamed response chunks. If no chunk arrives in time, the request is aborted.</li>\n<li><code>setCacheKey</code> - Ensure a cache key is always set for designated provider.</li>\n</ul>\n<p>You can also configure <a href=\"models.html#local\">local models</a>. <a href=\"models.html\">Learn more</a>.</p>\n<hr />\n<h3 id=\"policies\">Policies</h3>\n<p>Use the <code>experimental.policies</code> option to allow or deny OpenCode actions on configured resources. Currently, policies can control which providers OpenCode may use.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;experimental&quot;: {\n    &quot;policies&quot;: [\n      {\n        &quot;effect&quot;: &quot;deny&quot;,\n        &quot;action&quot;: &quot;provider.use&quot;,\n        &quot;resource&quot;: &quot;openai&quot;\n      }\n    ]\n  }\n}\n</code></pre>\n<p><a href=\"policies.html\">Learn more about policies here</a>.</p>\n<hr />\n<h3 id=\"image-attachments\">Image attachments</h3>\n<p>OpenCode normalizes image attachments before sending them to the model. By default, images are resized when they exceed <code>2000x2000</code> pixels or <code>5242880</code> base64 bytes.</p>\n<p>Configure image attachment limits with the <code>attachment.image</code> option:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;attachment&quot;: {\n    &quot;image&quot;: {\n      &quot;auto_resize&quot;: true,\n      &quot;max_width&quot;: 2000,\n      &quot;max_height&quot;: 2000,\n      &quot;max_base64_bytes&quot;: 5242880\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>auto_resize</code> - Resize images that exceed the configured limits before provider requests. Set to <code>false</code> to reject oversized images instead.</li>\n<li><code>max_width</code> - Maximum image width in pixels before resizing or rejection.</li>\n<li><code>max_height</code> - Maximum image height in pixels before resizing or rejection.</li>\n<li><code>max_base64_bytes</code> - Maximum encoded image payload size. This is the base64 payload size, not the original file size.</li>\n</ul>\n<p>If an image still cannot fit after resizing, OpenCode omits oversized tool-result images or fails oversized user-provided images with an image size error.</p>\n<hr />\n<h4 id=\"provider-specific-options\">Provider-Specific Options</h4>\n<p>Some providers support additional configuration options beyond the generic <code>timeout</code> and <code>apiKey</code> settings.</p>\n<h5 id=\"amazon-bedrock\">Amazon Bedrock</h5>\n<p>Amazon Bedrock supports AWS-specific configuration:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;provider&quot;: {\n    &quot;amazon-bedrock&quot;: {\n      &quot;options&quot;: {\n        &quot;region&quot;: &quot;us-east-1&quot;,\n        &quot;profile&quot;: &quot;my-aws-profile&quot;,\n        &quot;endpoint&quot;: &quot;https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com&quot;\n      }\n    }\n  }\n}\n</code></pre>\n<ul>\n<li><code>region</code> - AWS region for Bedrock (defaults to <code>AWS_REGION</code> env var or <code>us-east-1</code>)</li>\n<li><code>profile</code> - AWS named profile from <code>~/.aws/credentials</code> (defaults to <code>AWS_PROFILE</code> env var)</li>\n<li><code>endpoint</code> - Custom endpoint URL for VPC endpoints. This is an alias for the generic <code>baseURL</code> option using AWS-specific terminology. If both are specified, <code>endpoint</code> takes precedence.</li>\n</ul>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Bearer tokens (<code>AWS_BEARER_TOKEN_BEDROCK</code> or <code>/connect</code>) take precedence over profile-based authentication. See <a href=\"providers.html#authentication-precedence\">authentication precedence</a> for details.</p>\n</div>\n<p><a href=\"providers.html#amazon-bedrock\">Learn more about Amazon Bedrock configuration</a>.</p>\n<hr />\n<h3 id=\"themes\">Themes</h3>\n<p>Set your UI theme in <code>tui.json</code>.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/tui.json&quot;,\n  &quot;theme&quot;: &quot;tokyonight&quot;\n}\n</code></pre>\n<p><a href=\"themes.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"agents\">Agents</h3>\n<p>You can configure specialized agents for specific tasks through the <code>agent</code> option.</p>\n<pre><code class=\"language-jsonc\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;agent&quot;: {\n    &quot;code-reviewer&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-sonnet-4-5&quot;,\n      &quot;prompt&quot;: &quot;You are a code reviewer. Focus on security, performance, and maintainability.&quot;,\n      &quot;tools&quot;: {\n        // Disable file modification tools for review-only agent\n        &quot;write&quot;: false,\n        &quot;edit&quot;: false,\n      },\n    },\n  },\n}\n</code></pre>\n<p>You can also define agents using markdown files in <code>~/.config/opencode/agents/</code> or <code>.opencode/agents/</code>. <a href=\"agents.html\">Learn more here</a>.</p>\n<hr />\n<h3 id=\"default-agent\">Default agent</h3>\n<p>You can set the default agent using the <code>default_agent</code> option. This determines which agent is used when none is explicitly specified.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;default_agent&quot;: &quot;plan&quot;\n}\n</code></pre>\n<p>The default agent must be a primary agent (not a subagent). This can be a built-in agent like <code>\"build\"</code> or <code>\"plan\"</code>, or a <a href=\"agents.html\">custom agent</a> you've defined. If the specified agent doesn't exist or is a subagent, OpenCode will fall back to <code>\"build\"</code> with a warning.</p>\n<p>This setting applies across all interfaces: TUI, CLI (<code>opencode run</code>), desktop app, and GitHub Action.</p>\n<hr />\n<h3 id=\"subagent-depth\">Subagent depth</h3>\n<p>You can control how deeply subagents can invoke other subagents using the <code>subagent_depth</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;subagent_depth&quot;: 2\n}\n</code></pre>\n<p>The default is <code>1</code>, which allows primary agents to launch subagents but prevents those subagents from launching additional subagents. Set it to <code>2</code> to allow one additional level of nested subagents, or <code>0</code> to prevent all subagent launches.</p>\n<hr />\n<h3 id=\"sharing\">Sharing</h3>\n<p>You can configure the <a href=\"share.html\">share</a> feature through the <code>share</code> option.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;share&quot;: &quot;manual&quot;\n}\n</code></pre>\n<p>This takes:</p>\n<ul>\n<li><code>\"manual\"</code> - Allow manual sharing via commands (default)</li>\n<li><code>\"auto\"</code> - Automatically share new conversations</li>\n<li><code>\"disabled\"</code> - Disable sharing entirely</li>\n</ul>\n<p>By default, sharing is set to manual mode where you need to explicitly share conversations using the <code>/share</code> command.</p>\n<hr />\n<h3 id=\"commands\">Commands</h3>\n<p>You can configure custom commands for repetitive tasks through the <code>command</code> option.</p>\n<pre><code class=\"language-jsonc\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;command&quot;: {\n    &quot;test&quot;: {\n      &quot;template&quot;: &quot;Run the full test suite with coverage report and show any failures.\\nFocus on the failing tests and suggest fixes.&quot;,\n      &quot;description&quot;: &quot;Run tests with coverage&quot;,\n      &quot;agent&quot;: &quot;build&quot;,\n      &quot;model&quot;: &quot;anthropic/claude-haiku-4-5&quot;,\n    },\n    &quot;component&quot;: {\n      &quot;template&quot;: &quot;Create a new React component named $ARGUMENTS with TypeScript support.\\nInclude proper typing and basic structure.&quot;,\n      &quot;description&quot;: &quot;Create a new component&quot;,\n    },\n  },\n}\n</code></pre>\n<p>You can also define commands using markdown files in <code>~/.config/opencode/commands/</code> or <code>.opencode/commands/</code>. <a href=\"commands.html\">Learn more For example.</p>\n143: <p><code>txt\n144:  @general help me search for this function</code></p>\n145: </li>\n146: <li>\n147: <p><strong>Navigation between sessions</strong>: When subagents create child sessions, use <code>session_child_first</code> (default: <strong>\\<Leader>+Down</strong>) to enter the first child session from the parent.</p>\n148: </li>\n149: <li>\n150: <p>Once you are in a child session, use:\n151:    - <code>session_child_cycle</code> (default: <strong>Right</strong>) to cycle to the next child session\n152:    - <code>session_child_cycle_reverse</code> (default: <strong>Left</strong>) to cycle to the previous child session\n153:    - <code>session_parent</code> (default: <strong>Up</strong>) to return to the parent session</p>\n154: </li>\n155: </ol>\n156: <p>This lets you switch between the main conversation and specialized subagent work.</p>\n157: <hr />\n158: <h2 id=\"configure\">Configure</h2>\n159: <p>You can customize the built-in agents or create your own through configuration. Focus on security, performance, and maintainability.&quot;,\n188:       &quot;permission&quot;: {\n189:         &quot;edit&quot;: &quot;deny&quot;\n190:       }\n191:     }\n192:   }\n193: }\n194: </code></pre>\n195: <hr />\n196: <h3 id=\"markdown\">Markdown</h3>\n197: <p>You can also define agents using markdown files. Place them in:</p>\n198: <ul>\n199: <li>Global: <code>~/.config/opencode/agents/</code></li>\n200: <li>Per-project: <code>.opencode/agents/</code></li>\n201: </ul>\n202: <pre><code class=\"language-markdown\">---\n203: description: Reviews code for quality and best practices\n204: mode: subagent\n205: model: anthropic/claude-sonnet-4-20250514\n206: temperature: 0.1\n207: permission:\n208:   edit: deny\n209:   bash: deny\n210: ---\n211: \n212: You are in code review mode. Focus on:\n213: \n214: - Code quality and best practices\n215: - Potential bugs and edge cases\n216: - Performance implications\n217: - Security considerations\n218: \n219: Provide constructive feedback without making direct changes.\n220: </code></pre>\n221: <p>The markdown file name becomes the agent name. For example, <code>review.md</code> creates a <code>review</code> agent.</p>\n222: <hr />\n223: <h2 id=\"options\">Options</h2>\n224: <p>Let's look at these configuration options in detail.</p>\n225: <hr />\n226: <h3 id=\"description\">Description</h3>\n227: <p>Use the <code>description</code> option to provide a brief description of what the agent does and when to use it.</p>\n228: <pre><code class=\"language-json\">{\n229:   &quot;agent&quot;: {\n230:     &quot;review&quot;: {\n231:       &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n232:     }\n233:   }\n234: }\n235: </code></pre>\n236: <p>This is a <strong>required</strong> config option.</p>\n237: <hr />\n238: <h3 id=\"temperature\">Temperature</h3>\n239: <p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code> config.</p>\n240: <p>Lower values make responses more focused and deterministic, while higher values increase creativity and variability.</p>\n241: <pre><code class=\"language-json\">{\n242:   &quot;agent&quot;: {\n243:     &quot;plan&quot;: {\n244:       &quot;temperature&quot;: 0.1\n245:     },\n246:     &quot;creative&quot;: {\n247:       &quot;temperature&quot;: 0.8\n248:     }\n249:   }\n250: }\n251: </code></pre>\n252: <p>Temperature values typically range from 0.0 to 1.0:</p>\n253: <ul>\n254: <li><strong>0.0-0.2</strong>: Very focused and deterministic responses, ideal for code analysis and planning</li>\n255: <li><strong>0.3-0.5</strong>: Balanced responses with some creativity, good for general development tasks</li>\n256: <li><strong>0.6-1.0</strong>: More creative and varied responses, useful for brainstorming and exploration</li>\n257: </ul>\n258: <pre><code class=\"language-json\">{\n259:   &quot;agent&quot;: {\n260:     &quot;analyze&quot;: {\n261:       &quot;temperature&quot;: 0.1,\n262:       &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n263:     },\n264:     &quot;build&quot;: {\n265:       &quot;temperature&quot;: 0.3\n266:     },\n267:     &quot;brainstorm&quot;: {\n268:       &quot;temperature&quot;: 0.7,\n269:       &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n270:     }\n271:   }\n272: }\n273: </code></pre>\n274: <p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen models.</p>\n275: <hr />\n276: <h3 id=\"max-steps\">Max steps</h3>\n277: <p>Control the maximum number of agentic iterations an agent can perform before being forced to respond with text only. This allows users who wish to control costs to set a limit on agentic actions.</p>\n278: <p>If this is not set, the agent will continue to iterate until the model chooses to stop or the user interrupts the session.</p>\n279: <pre><code class=\"language-json\">{\n280:   &quot;agent&quot;: {\n281:     &quot;quick-thinker&quot;: {\n282:       &quot;description&quot;: &quot;Fast reasoning with limited iterations&quot;,\n283:       &quot;prompt&quot;: &quot;You are a quick thinker. Solve problems with minimal steps.&quot;,\n284:       &quot;steps&quot;: 5\n285:     }\n286:   }\n287: }\n288: </code></pre>\n289: <p>When the limit is reached, the agent receives a special system prompt instructing it to respond with a summarization of its work and recommended remaining tasks.</p>\n290: <div class=\"aside\">\n291: <div class=\"aside-t\">Caution</div>\n292: <p>The legacy <code>maxSteps</code> field is deprecated. Use <code>steps</code> instead.</p>\n293: </div>\n294: <hr />\n295: <h3 id=\"disable\">Disable</h3>\n296: <p>Set to <code>true</code> to disable the agent.</p>\n297: <pre><code class=\"language-json\">{\n298:   &quot;agent&quot;: {\n299:     &quot;review&quot;: {\n300:       &quot;disable&quot;: true\n301:     }\n302:   }\n303: }\n304: </code></pre>\n305: <hr />\n306: <h3 id=\"prompt\">Prompt</h3>\n307: <p>Specify a custom system prompt file for this agent with the <code>prompt</code> config. The prompt file should contain instructions specific to the agent's purpose.</p>\n308: <pre><code class=\"language-json\">{\n309:   &quot;agent&quot;: {\n310:     &quot;review&quot;: {\n311:       &quot;prompt&quot;: &quot;{file:./prompts/code-review.txt}&quot;\n312:     }\n313:   }\n314: }\n315: </code></pre>\n316: <p>This path is relative to where the config file is located. So this works for both the global OpenCode config and the project specific config.</p>\n317: <hr />\n318: <h3 id=\"model\">Model</h3>\n319: <p>Use the <code>model</code> config to override the model for this agent. Useful for using different models optimized for different tasks. For example, a faster model for planning, a more capable model for implementation.</p>\n320: <div class=\"aside\">\n321: <div class=\"aside-t\">Tip</div>\n322: <p>If you don’t specify a model, primary agents use the <a href=\"config.html#models\">model globally configured</a> while subagents will use the model of the primary agent that invoked the subagent.</p>\n323: </div>\n324: <pre><code class=\"language-json\">{\n325:   &quot;agent&quot;: {\n326:     &quot;plan&quot;: {\n327:       &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;\n328:     }\n329:   }\n330: }\n331: </code></pre>\n332: <p>The model ID in your OpenCode config uses the format <code>provider/model-id</code>. For example, if you're using <a href=\"zen.html\">OpenCode Zen</a>, you would use <code>opencode/gpt-5.1-codex</code> for GPT 5.1 Codex.</p>\n333: <hr />\n334: <h3 id=\"tools-deprecated\">Tools (deprecated)</h3>\n335: <p><code>tools</code> is <strong>deprecated</strong>. Prefer the agent's <a href=\"#permissions\"><code>permission</code></a> field for new configs, updates and more fine-grained control.</p>\n336: <p>Allows you to control which tools are available in this agent. You can enable or disable specific tools by setting them to <code>true</code> or <code>false</code>. In an agent's <code>tools</code> config, <code>true</code> is equivalent to <code>{\"*\": \"allow\"}</code> permission and <code>false</code> is equivalent to <code>{\"*\": \"deny\"}</code> permission.</p>\n337: <pre><code class=\"language-json\">{\n338:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n339:   &quot;tools&quot;: {\n340:     &quot;write&quot;: true,\n341:     &quot;bash&quot;: true\n342:   },\n343:   &quot;agent&quot;: {\n344:     &quot;plan&quot;: {\n345:       &quot;tools&quot;: {\n346:         &quot;write&quot;: false,\n347:         &quot;bash&quot;: false\n348:       }\n349:     }\n350:   }\n351: }\n352: </code></pre>\n353: <div class=\"aside\">\n354: <div class=\"aside-t\">Note</div>\n355: <p>The agent-specific config overrides the global config.</p>\n356: </div>\n357: <p>You can also use wildcards in legacy <code>tools</code> entries to control multiple tools at once. For example, to disable all tools from an MCP server:</p>\n358: <pre><code class=\"language-json\">{\n359:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n360:   &quot;agent&quot;: {\n361:     &quot;readonly&quot;: {\n362:       &quot;tools&quot;: {\n363:         &quot;mymcp_*&quot;: false,\n364:         &quot;write&quot;: false,\n365:         &quot;edit&quot;: false\n366:       }\n367:     }\n368:   }\n369: }\n370: </code></pre>\n371: <p><a href=\"tools.html\">Learn more about tools</a>.</p>\n372: <hr />\n373: <h3 id=\"permissions\">Permissions</h3>\n374: <p>You can configure permissions to manage what actions an agent can take. &quot;agent&quot;: {\n470:     &quot;build&quot;: {\n471:       &quot;permission&quot;: {\n472:         &quot;edit&quot;: &quot;ask&quot;\n473:       }\n474:     }\n475:   }\n476: }\n477: {\n500:         &quot;bash&quot;: {\n501:           &quot;git push&quot;: &quot;ask&quot;,\n502:           &quot;grep *&quot;: &quot;allow&quot;\n503:         }\n504:       }\n505:     }\n506:   }\n507: }\n508: </code></pre>\n509: <p>This can take a glob pattern.</p>\n510: <pre><code class=\"language-json\">{\n511:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n512:   &quot;agent&quot;: {\n513:     &quot;build&quot;: {\n514:       &quot;permission&quot;: {\n515:         &quot;bash&quot;: {\n516:           &quot;git *&quot;: &quot;ask&quot;\n517:         }\n518: &quot;https://opencode.ai/config.json&quot;,\n527:   &quot;agent&quot;: {\n528:     &quot;build&quot;: {\n529:       &quot;permission&quot;: {\n530:         &quot;bash&quot;: {\n531: href=\"permissions.html\">Learn more about permissions</a>.</p>\n540: <hr />\n541: <h3 id=\"mode\">Mode</h3>\n542: <p>Control the agent's mode with the <code>mode</code> config. The <code>mode</code> option is used to determine how the agent can be used.</p>\n543: <pre><code class=\"language-json\">{\n544:   &quot;agent&quot;: {\n545:     &quot;review&quot;: {\n546:       &quot;mode&quot;: &quot;subagent&quot;\n547:     }\n548:   }\n549: }\n550: </code></pre>\n551: <p>The <code>mode</code> option can be set to <code>primary</code>, <code>subagent</code>, or <code>all</code>. If no <code>mode</code> is specified, it defaults to <code>all</code>.</p>\n552: <hr />\n553: <h3 id=\"hidden\">Hidden</h3>\n554: <p>Hide a subagent from the <code>@</code> autocomplete menu with <code>hidden: true</code>. Useful for internal subagents that should only be invoked programmatically by other agents via the Task tool.</p>\n555: <pre><code class=\"language-json\">{\n556:   &quot;agent&quot;: {\n557:     &quot;internal-helper&quot;: {\n558:       &quot;mode&quot;: &quot;subagent&quot;,\n559:       &quot;hidden&quot;: true\n560:     }\n561:   }\n562: }\n563: </code></pre>\n564: <p>This only affects user visibility in the autocomplete menu. Hidden agents can still be invoked by the model via the Task tool if permissions allow.</p>\n565: <div class=\"aside\">\n566: <div class=\"aside-t\">Note</div>\n567: <p>Only applies to <code>mode: subagent</code> agents.</p>\n568: </div>\n569: <hr />\n570: <h3 id=\"task-permissions\">Task permissions</h3>\n571: <p>Control which subagents an agent can invoke via the Task tool with <code>permission.task</code>. Uses glob patterns for flexible matching.</p>\n572: <pre><code class=\"language-json\">{\n573:   &quot;agent&quot;: {\n574:     &quot;orchestrator&quot;: {\n575:       &quot;mode&quot;: &quot;primary&quot;,\n576:       &quot;permission&quot;: {\n577:         &quot;task&quot;: {\n578:           &quot;*&quot;: &quot;deny&quot;,\n579:           &quot;orchestrator-*&quot;: &quot;allow&quot;,\n580:           &quot;code-reviewer&quot;: &quot;ask&quot;\n581:         }\n582:       }\n583:     }\n584:   }\n585: }\n586: </code></pre>\n587: <p>When set to <code>deny</code>, the subagent is removed from the Task tool description entirely, so the model won't attempt to invoke it.</p>\n588: <div class=\"aside\">\n589: <div class=\"aside-t\">Tip</div>\n590: <p>Rules are evaluated in order, and the <strong>last matching rule wins</strong>. In the example above, <code>orchestrator-planner</code> matches both <code>*</code> (deny) and <code>orchestrator-*</code> (allow), but since <code>orchestrator-*</code> comes after <code>*</code>, the result is <code>allow</code>.</p>\n591: </div>\n592: <div class=\"aside\">\n593: <div class=\"aside-t\">Tip</div>\n594: <p>Users can always invoke any subagent directly via the <code>@</code> autocomplete menu, even if the agent's task permissions would deny it.</p>\n595: </div>\n596: <hr />\n597: <h3 id=\"color\">Color</h3>\n598: <p>Customize the agent's visual appearance in the UI with the <code>color</code> option. This affects how the agent appears in the interface.</p>\n599: <p>Use a valid hex color (e.g., <code>#FF5733</code>) or theme color: <code>primary</code>, <code>secondary</code>, <code>accent</code>, <code>success</code>, <code>warning</code>, <code>error</code>, <code>info</code>.</p>\n600: <pre><code class=\"language-json\">{\n601:   &quot;agent&quot;: {\n602:     &quot;creative&quot;: {\n603:       &quot;color&quot;: &quot;#ff6b6b&quot;\n604:     },\n605:     &quot;code-reviewer&quot;: {\n606:       &quot;color&quot;: &quot;accent&quot;\n607:     }\n608:   }\n609: }\n610: </code></pre>\n611: <hr />\n612: <h3 id=\"top-p\">Top P</h3>\n613: <p>Control response diversity with the <code>top_p</code> option. Alternative to temperature for controlling randomness.</p>\n614: <pre><code class=\"language-json\">{\n615:   &quot;agent&quot;: {\n616:     &quot;brainstorm&quot;: {\n617:       &quot;top_p&quot;: 0.9\n618:     }\n619:   }\n620: }\n621: </code></pre>\n622: <p>Values range from 0.0 to 1.0. They allow you to create focused tools with custom prompts, models, and tool access.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Use the plan agent to analyze code and review suggestions without making any code changes.</p>\n</div>\n<p>You can switch between agents during a session or invoke them with the <code>@</code> mention.</p>\n<hr />\n<h2 id=\"types\">Types</h2>\n<p>There are two types of agents in OpenCode; primary agents and subagents.</p>\n<hr />\n<h3 id=\"primary-agents\">Primary agents</h3>\n<p>Primary agents are the main assistants you interact with directly. You can cycle through them using the <strong>Tab</strong> key, or your configured <code>switch_agent</code> keybind. These agents handle your main conversation. Tool access is configured via permissions — for example, Build has all tools enabled while Plan is restricted.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>You can use the <strong>Tab</strong> key to switch between primary agents during a session.</p>\n</div>\n<p>OpenCode comes with two built-in primary agents, <strong>Build</strong> and <strong>Plan</strong>. We'll\nlook at these below.</p>\n<hr />\n<h3 id=\"subagents\">Subagents</h3>\n<p>Subagents are specialized assistants that primary agents can invoke for specific tasks. You can also manually invoke them by <strong>@ mentioning</strong> them in your messages.</p>\n<p>OpenCode comes with three built-in subagents, <strong>General</strong>, <strong>Explore</strong>, and <strong>Scout</strong>. We'll look at this below.</p>\n<hr />\n<h2 id=\"built-in\">Built-in</h2>\n<p>OpenCode comes with two built-in primary agents and three built-in subagents.</p>\n<hr />\n<h3 id=\"use-build\">Use build</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Build is the <strong>default</strong> primary agent with all tools enabled. This is the standard agent for development work where you need full access to file operations and system commands.</p>\n<hr />\n<h3 id=\"use-plan\">Use plan</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>A restricted agent designed for planning and analysis. We use a permission system to give you more control and prevent unintended changes.\nBy default, all of the following are set to <code>ask</code>:</p>\n<ul>\n<li><code>file edits</code>: All writes, patches, and edits</li>\n<li><code>bash</code>: All bash commands</li>\n</ul>\n<p>This agent is useful when you want the LLM to analyze code, suggest changes, or create plans without making any actual modifications to your codebase.</p>\n<hr />\n<h3 id=\"use-general\">Use general</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A general-purpose agent for researching complex questions and executing multi-step tasks. Has full tool access (except todo), so it can make file changes when needed. Use this to run multiple units of work in parallel.</p>\n<hr />\n<h3 id=\"use-explore\">Use explore</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A fast, read-only agent for exploring codebases. Cannot modify files. Use this when you need to quickly find files by patterns, search code for keywords, or answer questions about the codebase.</p>\n<hr />\n<h3 id=\"use-scout\">Use scout</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A read-only agent for external docs and dependency research. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h3 id=\"use-summary\">Use summary</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Hidden system agent that creates session summaries. It runs automatically and is not selectable in the UI.</p>\n<hr />\n<h2 id=\"usage\">Usage</h2>\n<ol>\n<li>\n<p>For primary agents, use the <strong>Tab</strong> key to cycle through them during a session. You can also use your configured <code>switch_agent</code> keybind.</p>\n</li>\n<li>\n<p>Subagents can be invoked:\n   - <strong>Automatically</strong> by primary agents for specialized tasks based on their descriptions.\n   - Manually by <strong>@ mentioning</strong> a subagent in your message. &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n    }\n  }\n}\n</code></pre>\n<p>This is a <strong>required</strong> config option.</p>\n<hr />\n<h3 id=\"temperature\">Temperature</h3>\n<p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code>    &quot;plan&quot;: {\n      &quot;temperature&quot;: 0.1\n    },\n    &quot;creative&quot;: {\n      &quot;temperature&quot;: 0.8\n    }\n  }\n}\n</code></pre>\n<p>Temperature values typically range from 0.0 to 1.0:</p>\n<ul>\n<li><strong>0.0-0.2</strong>: Very focused and deterministic responses, ideal for code analysis and planning</li>\n<li><strong>0.3-0.5</strong>: Balanced responses with class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;analyze&quot;: {\n      &quot;temperature&quot;: 0.1,\n      &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n    },\n    &quot;build&quot;: {\n      &quot;temperature&quot;: 0.3\n    },\n    &quot;brainstorm&quot;: {\n      &quot;temperature&quot;: 0.7,\n      &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen You can enable or disable specific tools by setting them to <code>true</code> or <code>false</code>.
