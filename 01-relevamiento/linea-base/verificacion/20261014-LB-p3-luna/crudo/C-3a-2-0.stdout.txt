We'll look at this below.</p>\n92: <hr />\n93: <h2 id=\"built-in\">Built-in</h2>\n94: <p>OpenCode comes with two built-in primary agents and three built-in subagents.</p>\n95: <hr />\n96: <h3 id=\"use-build\">Use build</h3>\n97: <p><em>Mode</em>: <code>primary</code></p>\n98: <p>Build is the <strong>default</strong> primary agent with all tools enabled. This is the standard agent for development work where you need full access to file operations and system commands.</p>\n99: <hr />\n100: <h3 id=\"use-plan\">Use plan</h3>\n101: <p><em>Mode</em>: <code>primary</code></p>\n102: <p>A restricted agent designed for planning and analysis. We use a permission system to give you more control and prevent unintended changes.\n103: By default, all of the following are set to <code>ask</code>:</p>\n104: <ul>\n105: <li><code>file edits</code>: All writes, patches, and edits</li>\n106: <li><code>bash</code>: All bash commands</li>\n107: </ul>\n108: <p>This agent is useful when you want the LLM to analyze code, suggest changes, or create plans without making any actual modifications to your codebase.</p>\n109: <hr />\n110: <h3 id=\"use-general\">Use general</h3>\n111: <p><em>Mode</em>: <code>subagent</code></p>\n112: <p>A general-purpose agent for researching complex questions and executing multi-step tasks. Has full tool access (except todo), so it can make file changes when needed. Use this to run multiple units of work in parallel.</p>\n113: <hr />\n114: <h3 id=\"use-explore\">Use explore</h3>\n115: <p><em>Mode</em>: <code>subagent</code></p>\n116: <p>A fast, read-only agent for exploring codebases. Cannot modify files. Use this when you need to quickly find files by patterns, search code for keywords, or answer questions about the codebase.</p>\n117: <hr />\n118: <h3 id=\"use-scout\">Use scout</h3>\n119: <p><em>Mode</em>: <code>subagent</code></p>\n120: <p>A read-only agent for external docs and dependency research. Use this when you need to clone a dependency repository into OpenCode's managed cache, inspect library source, or cross-reference local code against upstream implementations without modifying your workspace.</p>\n121: <hr />\n122: <h3 id=\"use-compaction\">Use compaction</h3>\n123: <p><em>Mode</em>: <code>primary</code></p>\n124: <p>Hidden system agent that compacts long context into a smaller summary. It runs automatically when needed and is not selectable in the UI.</p>\n125: <hr />\n126: <h3 id=\"use-title\">Use title</h3>\n127: <p><em>Mode</em>: <code>primary</code></p>\n128: <p>Hidden system agent that generates short session titles. It runs automatically and is not selectable in the UI.</p>\n129: <hr />\n130: <h3 id=\"use-summary\">Use summary</h3>\n131: <p><em>Mode</em>: <code>primary</code></p>\n132: <p>Hidden system agent that creates session summaries. It runs automatically and is not selectable in the UI.</p>\n133: <hr />\n134: <h2 id=\"usage\">Usage</h2>\n135: <ol>\n136: <li>\n137: <p>For primary agents, use the <strong>Tab</strong> key to cycle through them during a session. You can also use your configured <code>switch_agent</code> keybind.</p>\n138: </li>\n139: <li>\n140: <p>Subagents can be invoked:\n141:    - <strong>Automatically</strong> by primary agents for specialized tasks based on their descriptions.\n142:    - Manually by <strong>@ mentioning</strong> a subagent in your message. For example.</p>\n143: <p><code>txt\n144:  @general help me search for this function</code></p>\n145: </li>\n146: <li>\n147: <p><strong>Navigation between sessions</strong>: When subagents create child sessions, use <code>session_child_first</code> (default: <strong>\\<Leader>+Down</strong>) to enter the first child session from the parent.</p>\n148: </li>\n149: <li>\n150: <p>Once you are in a child session, use:\n151:    - <code>session_child_cycle</code> (default: <strong>Right</strong>) to cycle to the next child session\n152:    - <code>session_child_cycle_reverse</code> (default: <strong>Left</strong>) to cycle to the previous child session\n153:    - <code>session_parent</code> (default: <strong>Up</strong>) to return to the parent session</p>\n154: </li>\n155: </ol>\n156: <p>This lets you switch between the main conversation and specialized subagent work.</p>\n157: <hr />\n158: <h2 id=\"configure\">Configure</h2>\n159: <p>You can customize the built-in agents or create your own through configuration. Agents can be configured in two ways:</p>\n160: <hr />\n161: <h3 id=\"json\">JSON</h3>\n162: <p>Configure agents in your <code>opencode.json</code> config file:</p>\n163: <pre><code class=\"language-json\">{\n164:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n165:   &quot;agent&quot;: {\n166:     &quot;build&quot;: {\n167:       &quot;mode&quot;: &quot;primary&quot;,\n168:       &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n169:       &quot;prompt&quot;: &quot;{file:./prompts/build.txt}&quot;,\n170:       &quot;permission&quot;: {\n171:         &quot;edit&quot;: &quot;allow&quot;,\n172:         &quot;bash&quot;: &quot;allow&quot;\n173:       }\n174:     },\n175:     &quot;plan&quot;: {\n176:       &quot;mode&quot;: &quot;primary&quot;,\n177:       &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;,\n178:       &quot;permission&quot;: {\n179:         &quot;edit&quot;: &quot;deny&quot;,\n180:         &quot;bash&quot;: &quot;deny&quot;\n181:       }\n182:     },\n183:     &quot;code-reviewer&quot;: {\n184:       &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;,\n185:       &quot;mode&quot;: &quot;subagent&quot;,\n186:       &quot;model&quot;: &quot;anthropic/claude-sonnet-4-20250514&quot;,\n187:       &quot;prompt&quot;: &quot;You are a code reviewer. Focus on security, performance, and maintainability.&quot;,\n188:       &quot;permission&quot;: {\n189:         &quot;edit&quot;: &quot;deny&quot;\n190:       }\n191:     }\n192:   }\n193: }\n194: </code></pre>\n195: <hr />\n196: <h3 id=\"markdown\">Markdown</h3>\n197: <p>You can also define agents using markdown files. Place them in:</p>\n198: <ul>\n199: <li>Global: <code>~/.config/opencode/agents/</code></li>\n200: <li>Per-project: <code>.opencode/agents/</code></li>\n201: </ul>\n202: <pre><code class=\"language-markdown\">---\n203: description: Reviews code for quality and best practices\n204: mode: subagent\n205: model: anthropic/claude-sonnet-4-20250514\n206: temperature: 0.1\n207: permission:\n208:   edit: deny\n209:   bash: deny\n210: ---\n211: \n212: You are in code review mode. Focus on:\n213: \n214: - Code quality and best practices\n215: - Potential bugs and edge cases\n216: - Performance implications\n217: - Security considerations\n218: \n219: Provide constructive feedback without making direct changes.\n220: </code></pre>\n221: <p>The markdown file name becomes the agent name. For example, <code>review.md</code> creates a <code>review</code> agent.</p>\n222: <hr />\n223: <h2 id=\"options\">Options</h2>\n224: <p>Let's look at these configuration options in detail.</p>\n225: <hr />\n226: <h3 id=\"description\">Description</h3>\n227: <p>Use the <code>description</code> option to provide a brief description of what the agent does and when to use it.</p>\n228: <pre><code class=\"language-json\">{\n229:   &quot;agent&quot;: {\n230:     &quot;review&quot;: {\n231:       &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n232:     }\n233:   }\n234: }\n235: </code></pre>\n236: <p>This is a <strong>required</strong> config option.</p>\n237: <hr />\n238: <h3 id=\"temperature\">Temperature</h3>\n239: <p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code> config.</p>\n240: <p>Lower values make responses more focused and deterministic, while higher values increase creativity and variability.</p>\n241: <pre><code class=\"language-json\">{\n242:   &quot;agent&quot;: {\n243:     &quot;plan&quot;: {\n244:       &quot;temperature&quot;: 0.1\n245:     },\n246:     &quot;creative&quot;: {\n247:       &quot;temperature&quot;: 0.8\n248:     }\n249:   }\n250: }\n251: </code></pre>\n252: <p>Temperature values typically range from 0.0 to 1.0:</p>\n253: <ul>\n254: <li><strong>0.0-0.2</strong>: Very focused and deterministic responses, ideal for code analysis and planning</li>\n255: <li><strong>0.3-0.5</strong>: Balanced responses with some creativity, good for general development tasks</li>\n256: <li><strong>0.6-1.0</strong>: More creative and varied responses, useful for brainstorming and exploration</li>\n257: </ul>\n258: <pre><code class=\"language-json\">{\n259:   &quot;agent&quot;: {\n260:     &quot;analyze&quot;: {\n261:       &quot;temperature&quot;: 0.1,\n262:       &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n263:     },\n264:     &quot;build&quot;: {\n265:       &quot;temperature&quot;: 0.3\n266:     },\n267:     &quot;brainstorm&quot;: {\n268:       &quot;temperature&quot;: 0.7,\n269:       &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n270:     }\n271:   }\n272: }\n273: </code></pre>\n274: <p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen models.</p>\n275: <hr />\n276: <h3 id=\"max-steps\">Max steps</h3>\n277: <p>Control the maximum number of agentic iterations an agent can perform before being forced to respond with text only. This allows users who wish to control costs to set a limit on agentic actions.</p>\n278: <p>If this is not set, the agent will continue to iterate until the model chooses to stop or the user interrupts the session.</p>\n279: <pre><code class=\"language-json\">{\n280:   &quot;agent&quot;: {\n281:     &quot;quick-thinker&quot;: {\n282:       &quot;description&quot;: &quot;Fast reasoning with limited iterations&quot;,\n283:       &quot;prompt&quot;: &quot;You are a quick thinker. Solve problems with minimal steps.&quot;,\n284:       &quot;steps&quot;: 5\n285:     }\n286:   }\n287: }\n288: </code></pre>\n289: <p>When the limit is reached, the agent receives a special system prompt instructing it to respond with a summarization of its work and recommended remaining tasks.</p>\n290: <div class=\"aside\">\n291: <div class=\"aside-t\">Caution</div>\n292: <p>The legacy <code>maxSteps</code> field is deprecated. Use <code>steps</code> instead.</p>\n293: </div>\n294: <hr />\n295: <h3 id=\"disable\">Disable</h3>\n296: <p>Set to <code>true</code> to disable the agent.</p>\n297: <pre><code class=\"language-json\">{\n298:   &quot;agent&quot;: {\n299:     &quot;review&quot;: {\n300:       &quot;disable&quot;: true\n301:     }\n302:   }\n303: }\n304: </code></pre>\n305: <hr />\n306: <h3 id=\"prompt\">Prompt</h3>\n307: <p>Specify a custom system prompt file for this agent with the <code>prompt</code> config. The prompt file should contain instructions specific to the agent's purpose.</p>\n308: <pre><code class=\"language-json\">{\n309:   &quot;agent&quot;: {\n310:     &quot;review&quot;: {\n311:       &quot;prompt&quot;: &quot;{file:./prompts/code-review.txt}&quot;\n312:     }\n313:   }\n314: }\n315: </code></pre>\n316: <p>This path is relative to where the config file is located. So this works for both the global OpenCode config and the project specific config.</p>\n317: <hr />\n318: <h3 id=\"model\">Model</h3>\n319: <p>Use the <code>model</code> config to override the model for this agent. Useful for using different models optimized for different tasks. For example, a faster model for planning, a more capable model for implementation.</p>\n320: <div class=\"aside\">\n321: <div class=\"aside-t\">Tip</div>\n322: <p>If you don’t specify a model, primary agents use the <a href=\"config.html#models\">model globally configured</a> while subagents will use the model of the primary agent that invoked the subagent.</p>\n323: </div>\n324: <pre><code class=\"language-json\">{\n325:   &quot;agent&quot;: {\n326:     &quot;plan&quot;: {\n327:       &quot;model&quot;: &quot;anthropic/claude-haiku-4-20250514&quot;\n328:     }\n329:   }\n330: }\n331: </code></pre>\n332: <p>The model ID in your OpenCode config uses the format <code>provider/model-id</code>. For example, if you're using <a href=\"zen.html\">OpenCode Zen</a>, you would use <code>opencode/gpt-5.1-codex</code> for GPT 5.1 Codex.</p>\n333: <hr />\n334: <h3 id=\"tools-deprecated\">Tools (deprecated)</h3>\n335: <p><code>tools</code> is <strong>deprecated</strong>. Prefer the agent's <a href=\"#permissions\"><code>permission</code></a> field for new configs, updates and more fine-grained control.</p>\n336: <p>Allows you to control which tools are available in this agent. You can enable or disable specific tools by setting them to <code>true</code> or <code>false</code>. In an agent's <code>tools</code> config, <code>true</code> is equivalent to <code>{\"*\": \"allow\"}</code> permission and <code>false</code> is equivalent to <code>{\"*\": \"deny\"}</code> permission.</p>\n337: <pre><code class=\"language-json\">{\n338:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n339:   &quot;tools&quot;: {\n340:     &quot;write&quot;: true,\n341:     &quot;bash&quot;: true\n342:   },\n343:   &quot;agent&quot;: {\n344:     &quot;plan&quot;: {\n345:       &quot;tools&quot;: {\n346:         &quot;write&quot;: false,\n347:         &quot;bash&quot;: false\n348:       }\n349:     }\n350:   }\n351: }\n352: </code></pre>\n353: <div class=\"aside\">\n354: <div class=\"aside-t\">Note</div>\n355: <p>The agent-specific config overrides the global config.</p>\n356: </div>\n357: <p>You can also use wildcards in legacy <code>tools</code> entries to control multiple tools at once. For example, to disable all tools from an MCP server:</p>\n358: <pre><code class=\"language-json\">{\n359:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n360:   &quot;agent&quot;: {\n361:     &quot;readonly&quot;: {\n362:       &quot;tools&quot;: {\n363:         &quot;mymcp_*&quot;: false,\n364:         &quot;write&quot;: false,\n365:         &quot;edit&quot;: false\n366:       }\n367:     }\n368:   }\n369: }\n370: </code></pre>\n371: <p><a href=\"tools.html\">Learn more about tools</a>.</p>\n372: <hr />\n373: <h3 id=\"permissions\">Permissions</h3>\n374: <p>You can configure permissions to manage what actions an agent can take. }\n507: }\n508: </code></pre>\n509: <p>This can take a glob pattern.</p>\n510: <pre><code class=\"language-json\">{\n511:   &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n512: href=\"permissions.html\">Learn more about permissions</a>.</p>\n540: <hr />\n541: <h3 id=\"mode\">Mode</h3>\n542: <p>Control the agent's mode with the <code>mode</code> config. The <code>mode</code> option is used to determine how the agent can be used.</p>\n543: <pre><code class=\"language-json\">{\n544:   &quot;agent&quot;: {\n545:     &quot;review&quot;: {\n546:       &quot;mode&quot;: &quot;subagent&quot;\n547:     }\n548:   }\n549: }\n550: </code></pre>\n551: <p>The <code>mode</code> option can be set to <code>primary</code>, <code>subagent</code>, or <code>all</code>. If no <code>mode</code> is specified, it defaults to <code>all</code>.</p>\n552: <hr />\n553: <h3 id=\"hidden\">Hidden</h3>\n554: <p>Hide a subagent from the <code>@</code> autocomplete menu with <code>hidden: true</code>. Useful for internal subagents that should only be invoked programmatically by other agents via the Task tool.</p>\n555: <pre><code class=\"language-json\">{\n556:   &quot;agent&quot;: {\n557:     &quot;internal-helper&quot;: {\n558:       &quot;mode&quot;: &quot;subagent&quot;,\n559:       &quot;hidden&quot;: true\n560:     }\n561:   }\n562: }\n563: </code></pre>\n564: <p>This only affects user visibility in the autocomplete menu. Hidden agents can still be invoked by the model via the Task tool if permissions allow.</p>\n565: <div class=\"aside\">\n566: <div class=\"aside-t\">Note</div>\n567: <p>Only applies to <code>mode: subagent</code> agents.</p>\n568: </div>\n569: <hr />\n570: <h3 id=\"task-permissions\">Task permissions</h3>\n571: <p>Control which subagents an agent can invoke via the Task tool with <code>permission.task</code>. Uses glob patterns for flexible matching.</p>\n572: <pre><code class=\"language-json\">{\n573:   &quot;agent&quot;: {\n574:     &quot;orchestrator&quot;: {\n575:       &quot;mode&quot;: &quot;primary&quot;,\n576:       &quot;permission&quot;: {\n577:         &quot;task&quot;: {\n578:           &quot;*&quot;: &quot;deny&quot;,\n579:           &quot;orchestrator-*&quot;: &quot;allow&quot;,\n580:           &quot;code-reviewer&quot;: &quot;ask&quot;\n581:         }\n582:       }\n583:     }\n584:   }\n585: }\n586: </code></pre>\n587: <p>When set to <code>deny</code>, the subagent is removed from the Task tool description entirely, so the model won't attempt to invoke it.</p>\n588: <div class=\"aside\">\n589: <div class=\"aside-t\">Tip</div>\n590: <p>Rules are evaluated in order, and the <strong>last matching rule wins</strong>. You can cycle through them using the <strong>Tab</strong> key, or your configured <code>switch_agent</code> keybind. These agents handle your main conversation. Tool access is configured via permissions — for example, Build has all tools enabled while Plan is restricted.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>You can use the <strong>Tab</strong> key to switch between primary agents during a session.</p>\n</div>\n<p>OpenCode comes with two built-in primary agents, <strong>Build</strong> and <strong>Plan</strong>. We'll\nlook at these below.</p>\n<hr />\n<h3 id=\"subagents\">Subagents</h3>\n<p>Subagents are specialized assistants that primary agents can invoke for specific tasks. You can also manually invoke them by <strong>@ mentioning</strong> them in your messages.</p>\n<p>OpenCode comes with three built-in subagents, <strong>General</strong>, <strong>Explore</strong>, and <strong>Scout</strong>. We'll look at this below.</p>\n<hr />\n<h2 id=\"built-in\">Built-in</h2>\n<p>OpenCode comes with two built-in primary agents and three built-in subagents.</p>\n<hr />\n<h3 id=\"use-build\">Use build</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>Build is the <strong>default</strong> primary agent with all tools enabled. This is the standard agent for development work where you need full access to file operations and system commands.</p>\n<hr />\n<h3 id=\"use-plan\">Use plan</h3>\n<p><em>Mode</em>: <code>primary</code></p>\n<p>A restricted agent designed for planning and analysis. We use a permission system to give you more control and prevent unintended changes.\nBy default, all of the following are set to <code>ask</code>:</p>\n<ul>\n<li><code>file edits</code>: All writes, patches, and edits</li>\n<li><code>bash</code>: All bash commands</li>\n</ul>\n<p>This agent is useful when you want the LLM to analyze code, suggest changes, or create plans without making any actual modifications to your codebase.</p>\n<hr />\n<h3 id=\"use-general\">Use general</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A general-purpose agent for researching complex questions and executing multi-step tasks. Has full tool access (except todo), so it can make file changes when needed. Use this to run multiple units of work in parallel.</p>\n<hr />\n<h3 id=\"use-explore\">Use explore</h3>\n<p><em>Mode</em>: <code>subagent</code></p>\n<p>A fast, read-only agent for exploring codebases. You can also use your configured <code>switch_agent</code> keybind.</p>\n</li>\n<li>\n<p>Subagents can be invoked:\n   - <strong>Automatically</strong> by primary agents for specialized tasks based on their descriptions.\n   - Manually by <strong>@ mentioning</strong> a subagent in your message. &quot;agent&quot;: {\n    &quot;review&quot;: {\n      &quot;description&quot;: &quot;Reviews code for best practices and potential issues&quot;\n    }\n  }\n}\n</code></pre>\n<p>This is a <strong>required</strong> config option.</p>\n<hr />\n<h3 id=\"temperature\">Temperature</h3>\n<p>Control the randomness and creativity of the LLM's responses with the <code>temperature</code>    &quot;plan&quot;: {\n      &quot;temperature&quot;: 0.1\n    },\n    &quot;creative&quot;: {\n      &quot;temperature&quot;: 0.8\n    }\n  }\n}\n</code></pre>\n<p>Temperature values typically range class=\"language-json\">{\n  &quot;agent&quot;: {\n    &quot;analyze&quot;: {\n      &quot;temperature&quot;: 0.1,\n      &quot;prompt&quot;: &quot;{file:./prompts/analysis.txt}&quot;\n    },\n    &quot;build&quot;: {\n      &quot;temperature&quot;: 0.3\n    },\n    &quot;brainstorm&quot;: {\n      &quot;temperature&quot;: 0.7,\n      &quot;prompt&quot;: &quot;{file:./prompts/creative.txt}&quot;\n    }\n  }\n}\n</code></pre>\n<p>If no temperature is specified, OpenCode uses model-specific defaults; typically 0 for most models, 0.55 for Qwen
