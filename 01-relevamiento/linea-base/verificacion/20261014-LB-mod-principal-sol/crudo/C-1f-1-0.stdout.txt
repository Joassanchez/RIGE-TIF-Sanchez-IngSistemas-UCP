The old <code>tools</code> config is still supported for backwards compatibility.</p>\n<hr />\n<h2 id=\"actions\">Actions</h2>\n<p>Each permission rule resolves to one of:</p>\n<ul>\n<li><code>\"allow\"</code> — run without approval</li>\n<li><code>\"ask\"</code> — prompt for approval</li>\n<li><code>\"deny\"</code> — block the action</li>\n</ul>\n<hr />\n<h2 id=\"auto-mode\">Auto mode</h2>\n<p>Start OpenCode with <code>--auto</code> to automatically approve permission requests that are not explicitly denied.</p>\n<pre><code class=\"language-bash\">opencode --auto\n</code></pre>\n<p>You can also use auto mode with <a href=\"cli.html#run\"><code>opencode run</code></a>.</p>\n<pre><code class=\"language-bash\">opencode run --auto &quot;Refactor this module&quot;\n</code></pre>\n<p>Explicit <code>\"deny\"</code> rules are still enforced. Auto mode only changes requests that would otherwise ask for approval.</p>\n<p>In the TUI, open the command palette and select <strong>Enable auto-approve permissions</strong> or <strong>Disable auto-approve permissions</strong> to change modes. When auto mode is active, the prompt displays a muted <code>auto</code> indicator next to the current agent.</p>\n<hr />\n<h2 id=\"configuration\">Configuration</h2>\n<p>You can set permissions globally (with <code>*</code>), and override specific tools.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;*&quot;: &quot;ask&quot;,\n    &quot;bash&quot;: &quot;allow&quot;,\n    &quot;edit&quot;: &quot;deny&quot;\n  }\n}\n</code></pre>\n<p>You can also set all permissions at once:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: &quot;allow&quot;\n}\n</code></pre>\n<hr />\n<h2 id=\"granular-rules-object-syntax\">Granular Rules (Object Syntax)</h2>\n<p>For most permissions, you can use an object to apply different actions based on the tool input.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;bash&quot;: {\n      &quot;*&quot;: &quot;ask&quot;,\n      &quot;git *&quot;: &quot;allow&quot;,\n      &quot;npm *&quot;: &quot;allow&quot;,\n      &quot;rm *&quot;: &quot;deny&quot;,\n      &quot;grep *&quot;: &quot;allow&quot;\n    },\n    &quot;edit&quot;: {\n      &quot;*&quot;: &quot;deny&quot;,\n      &quot;packages/web/src/content/docs/*.mdx&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<p>Rules are evaluated by pattern match, with the <strong>last matching rule winning</strong>. A common pattern is to put the catch-all <code>\"*\"</code> rule first, and more specific rules after it.</p>\n<h3 id=\"wildcards\">Wildcards</h3>\n<p>Permission patterns use simple wildcard matching:</p>\n<ul>\n<li><code>*</code> matches zero or more of any character</li>\n<li><code>?</code> matches exactly one character</li>\n<li>All other characters match literally</li>\n</ul>\n<h3 id=\"home-directory-expansion\">Home Directory Expansion</h3>\n<p>You can use <code>~</code> or <code>$HOME</code> at the start of a pattern to reference your home directory. This is particularly useful for <a href=\"#external-directories\"><code>external_directory</code></a> rules.</p>\n<ul>\n<li><code>~/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>$HOME/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>~</code> -&gt; <code>/Users/username</code></li>\n</ul>\n<h3 id=\"external-directories\">External Directories</h3>\n<p>Use <code>external_directory</code> to allow tool calls that touch paths outside the working directory where OpenCode was started. This applies to any tool that takes a path as input (for example <code>read</code>, <code>edit</code>, <code>glob</code>, <code>grep</code>, and many <code>bash</code> commands).</p>\n<p>Home expansion (like <code>~/...</code>) only affects how a pattern is written. It does not make an external path part of the current workspace, so paths outside the working directory must still be allowed via <code>external_directory</code>.</p>\n<p>For example, this allows access to everything under <code>~/projects/personal/</code>:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;external_directory&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<p>Any directory allowed here inherits the same defaults as the current workspace. Since <a href=\"#defaults\"><code>read</code> defaults to <code>allow</code></a>, reads are also allowed for entries under <code>external_directory</code> unless overridden. Add explicit rules when a tool should be restricted in these paths, such as blocking edits while keeping reads:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;external_directory&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n    },\n    &quot;edit&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;deny&quot;\n    }\n  }\n}\n</code></pre>\n<p>Keep the list focused on trusted paths, and layer extra allow or deny rules as needed for other tools (for example <code>bash</code>).</p>\n<hr />\n<h2 id=\"available-permissions\">Available Permissions</h2>\n<p>OpenCode permissions are keyed by tool name, plus a couple of safety guards:</p>\n<ul>\n<li><code>read</code> — reading a file (matches the file path)</li>\n<li><code>edit</code> — all file modifications (covers <code>edit</code>, <code>write</code>, <code>patch</code>)</li>\n<li><code>glob</code> — file globbing (matches the glob pattern)</li>\n<li><code>grep</code> — content search (matches the regex pattern)</li>\n<li><code>bash</code> — running shell commands (matches parsed commands like <code>git status --porcelain</code>)</li>\n<li><code>task</code> — launching subagents (matches the subagent type)</li>\n<li><code>skill</code> — loading a skill (matches the skill name)</li>\n<li><code>lsp</code> — running LSP queries (currently non-granular)</li>\n<li><code>question</code> — asking the user questions during execution</li>\n<li><code>webfetch</code> — fetching a URL (matches the URL)</li>\n<li><code>websearch</code> — web search (matches the query)</li>\n<li><code>external_directory</code> — triggered when a tool touches paths outside the project working directory</li>\n<li><code>doom_loop</code> — triggered when the same tool call repeats 3 times with identical input</li>\n</ul>\n<hr />\n<h2 id=\"defaults\">Defaults</h2>\n<p>If you don’t specify anything, OpenCode starts from permissive defaults:</p>\n<ul>\n<li>Most permissions default to <code>\"allow\"</code>.</li>\n<li><code>doom_loop</code> and <code>external_directory</code> default to <code>\"ask\"</code>.</li>\n<li><code>read</code> is <code>\"allow\"</code>, but <code>.env</code> files are denied by default:</li>\n</ul>\n<pre><code class=\"language-json\">{\n  &quot;permission&quot;: {\n    &quot;read&quot;: {\n      &quot;*&quot;: &quot;allow&quot;,\n      &quot;*.env&quot;: &quot;deny&quot;,\n      &quot;*.env.*&quot;: &quot;deny&quot;,\n      &quot;*.env.example&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<hr />\n<h2 id=\"what-ask-does\">What “Ask” Does</h2>\n<p>When OpenCode prompts for approval, the UI offers three outcomes:</p>\n<ul>\n<li><code>once</code> — approve just this request</li>\n<li><code>always</code> — approve future requests matching the suggested patterns (for the rest of the current OpenCode session)</li>\n<li><code>reject</code> — deny the request</li>\n</ul>\n<p>The set of patterns that <code>always</code> would approve is provided by the tool (for example, bash approvals typically whitelist a safe command prefix like <code>git status*</code>).</p>\n<hr />\n<h2 id=\"agents\">Agents</h2>\n<p>You can override permissions per agent. Agent permissions are merged with the global config, and agent rules take precedence. <a href=\"agents.html#permissions\">Learn more</a> about agent permissions.</p>\n<div class=\"aside\">\n<div class=\"aside-t\">Note</div>\n<p>Refer to the <a href=\"#granular-rules-object-syntax\">Granular Rules (Object Syntax)</a> section above for more detailed pattern matching examples.</p>\n</div>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;bash&quot;: {\n      &quot;*&quot;: &quot;ask&quot;,\n      &quot;git *&quot;: &quot;allow&quot;,\n      &quot;git commit *&quot;: &quot;deny&quot;,\n      &quot;git push *&quot;: &quot;deny&quot;,\n      &quot;grep *&quot;: &quot;allow&quot;\n    }\n  },\n  &quot;agent&quot;: {\n    &quot;build&quot;: {\n      &quot;permission&quot;: {\n        &quot;bash&quot;: {\n          &quot;*&quot;: &quot;ask&quot;,\n          &quot;git *&quot;: &quot;allow&quot;,\n          &quot;git commit *&quot;: &quot;ask&quot;,\n          &quot;git push *&quot;: &quot;deny&quot;,\n          &quot;grep *&quot;: &quot;allow&quot;\n        }\n      }\n    }\n  }\n}\n</code></pre>\n<p>You can also configure agent permissions in Markdown:</p>\n<pre><code class=\"language-markdown\">---\ndescription: Code review without edits\nmode: subagent\npermission:\n  edit: deny\n  bash: ask\n  webfetch: deny\n---\n\nOnly analyze code and suggest changes.\n</code></pre>\n<div class=\"aside\">\n<div class=\"aside-t\">Tip</div>\n<p>Use pattern matching for commands with arguments. <code>\"grep *\"</code> allows <code>grep pattern file.txt</code>, while <code>\"grep\"</code> alone would block it.
