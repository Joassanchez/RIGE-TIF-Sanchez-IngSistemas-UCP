A common pattern is to put the catch-all <code>\"*\"</code> rule first, and more specific rules after it.</p>\n<h3 id=\"wildcards\">Wildcards</h3>\n<p>Permission patterns use simple wildcard matching:</p>\n<ul>\n<li><code>*</code> matches zero or more of any character</li>\n<li><code>?</code> matches exactly one character</li>\n<li>All other characters match literally</li>\n</ul>\n<h3 id=\"home-directory-expansion\">Home Directory Expansion</h3>\n<p>You can use <code>~</code> or <code>$HOME</code> at the start of a pattern to reference your home directory. This is particularly useful for <a href=\"#external-directories\"><code>external_directory</code></a> rules.</p>\n<ul>\n<li><code>~/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>$HOME/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>~</code> -&gt; <code>/Users/username</code></li>\n</ul>\n<h3 id=\"external-directories\">External Directories</h3>\n<p>Use <code>external_directory</code> to allow tool calls that touch paths outside the working directory where OpenCode was started. This applies to any tool that takes a path as input (for example <code>read</code>, <code>edit</code>, <code>glob</code>, <code>grep</code>, and many <code>bash</code> commands).</p>\n<p>Home expansion (like <code>~/...</code>) only affects how a pattern is written. It does not make an external path part of the current workspace, so paths outside the working directory must still be allowed via <code>external_directory</code>.</p>\n<p>For example, this allows access to everything under <code>~/projects/personal/</code>:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;external_directory&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<p>Any directory allowed here inherits the same defaults as the current workspace. Since <a href=\"#defaults\"><code>read</code> defaults to <code>allow</code></a>, reads are also allowed for entries under <code>external_directory</code> unless overridden. Add explicit rules when a tool should be restricted in these paths, such as blocking edits while keeping reads:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;external_directory&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n    },\n    &quot;edit&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;deny&quot;\n    }\n  }\n}\n</code></pre>\n<p>Keep the list focused on trusted paths, and layer extra allow or deny rules as needed for other tools (for example <code>bash</code>).</p>\n<hr />\n<h2 id=\"available-permissions\">Available Permissions</h2>\n<p>OpenCode permissions are keyed by tool name, plus a couple of safety guards:</p>\n<ul>\n<li><code>read</code> — reading a file (matches the file path)</li>\n<li><code>edit</code> — all file modifications (covers <code>edit</code>, <code>write</code>, <code>patch</code>)</li>\n<li><code>glob</code> — file globbing (matches the glob pattern)</li>\n<li><code>grep</code> — content search (matches the regex pattern)</li>\n<li><code>bash</code> — running shell commands (matches parsed commands like <code>git status --porcelain</code>)</li>\n<li><code>task</code> — launching subagents (matches the subagent type)</li>\n<li><code>skill</code> — loading a skill (matches the skill name)</li>\n<li><code>lsp</code> — running LSP queries (currently non-granular)</li>\n<li><code>question</code> — asking the user questions during execution</li>\n<li><code>webfetch</code> — fetching a URL (matches the URL)</li>\n<li><code>websearch</code> — web search (matches the query)</li>\n<li><code>external_directory</code> — triggered when a tool touches paths outside the project working directory</li>\n<li><code>doom_loop</code> — triggered when the same tool call repeats 3 times with identical input</li>\n</ul>\n<hr />\n<h2 id=\"defaults\">Defaults</h2>\n<p>If you don’t specify anything, OpenCode starts from permissive defaults:</p>\n<ul>\n<li>Most permissions default to <code>\"allow\"</code>.</li>\n<li><code>doom_loop</code> and <code>external_directory</code> default to <code>\"ask\"</code>.</li>\n<li><code>read</code> is <code>\"allow\"</code>, but <code>.env</code> files are denied by default:</li>\n</ul>\n<pre><code class=\"language-json\">{\n  &quot;permission&quot;: {\n    &quot;read&quot;: {\n      &quot;*&quot;: &quot;allow&quot;,\n      &quot;*.env&quot;: &quot;deny&quot;,\n      &quot;*.env.*&quot;: &quot;deny&quot;,\n      &quot;*.env.example&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<hr />\n<h2 id=\"what-ask-does\">What “Ask” Does</h2>\n<p>When OpenCode prompts for approval, the UI offers three outcomes:</p>\n<ul>\n<li><code>once</code> — approve just this
