When auto mode is active, the prompt displays a muted <code>auto</code> indicator next to the current agent.</p>\n<hr />\n<h2 id=\"configuration\">Configuration</h2>\n<p>You can set permissions globally (with <code>*</code>), and override specific tools.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;*&quot;: &quot;ask&quot;,\n    &quot;bash&quot;: &quot;allow&quot;,\n    &quot;edit&quot;: &quot;deny&quot;\n  }\n}\n</code></pre>\n<p>You can also set all permissions at once:</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: &quot;allow&quot;\n}\n</code></pre>\n<hr />\n<h2 id=\"granular-rules-object-syntax\">Granular Rules (Object Syntax)</h2>\n<p>For most permissions, you can use an object to apply different actions based on the tool input.</p>\n<pre><code class=\"language-json\">{\n  &quot;$schema&quot;: &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;bash&quot;: {\n      &quot;*&quot;: &quot;ask&quot;,\n      &quot;git *&quot;: &quot;allow&quot;,\n      &quot;npm *&quot;: &quot;allow&quot;,\n      &quot;rm *&quot;: &quot;deny&quot;,\n      &quot;grep *&quot;: &quot;allow&quot;\n    },\n    &quot;edit&quot;: {\n      &quot;*&quot;: &quot;deny&quot;,\n      &quot;packages/web/src/content/docs/*.mdx&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<p>Rules are evaluated by pattern match, with the <strong>last matching rule winning</strong>. A common pattern is to put the catch-all <code>\"*\"</code> rule first, and more specific rules after it.</p>\n<h3 id=\"wildcards\">Wildcards</h3>\n<p>Permission patterns use simple wildcard matching:</p>\n<ul>\n<li><code>*</code> matches zero or more of any character</li>\n<li><code>?</code> matches exactly one character</li>\n<li>All other characters match literally</li>\n</ul>\n<h3 id=\"home-directory-expansion\">Home Directory Expansion</h3>\n<p>You can use <code>~</code> or <code>$HOME</code> at the start of a pattern to reference your home directory. This is particularly useful for <a href=\"#external-directories\"><code>external_directory</code></a> rules.</p>\n<ul>\n<li><code>~/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>$HOME/projects/*</code> -&gt; <code>/Users/username/projects/*</code></li>\n<li><code>~</code> -&gt; <code>/Users/username</code></li>\n</ul>\n<h3 id=\"external-directories\">External Directories</h3>\n<p>Use <code>external_directory</code> to allow tool calls that touch paths outside the working directory where OpenCode was started. &quot;https://opencode.ai/config.json&quot;,\n  &quot;permission&quot;: {\n    &quot;external_directory&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;allow&quot;\n    },\n guards:</p>\n<ul>\n<li><code>read</code> — reading a file (matches the file path)</li>\n<li><code>edit</code> — all file modifications (covers <code>edit</code>, <code>write</code>, <code>patch</code>)</li>\n<li><code>glob</code> — file globbing (matches the glob pattern)</li>\n<li><code>grep</code> — content search (matches the regex pattern)</li>\n<li><code>bash</code> — running shell commands (matches parsed commands like <code>git status --porcelain</code>)</li>\n<li><code>task</code> — launching subagents (matches the subagent type)</li>\n<li><code>skill</code> — loading a skill (matches the skill name)</li>\n<li><code>lsp</code> — running LSP queries (currently non-granular)</li>\n<li><code>question</code> — asking the user questions during execution</li>\n<li><code>webfetch</code> — fetching a URL (matches the URL)</li>\n<li><code>websearch</code> — web search (matches the query)</li>\n<li><code>external_directory</code> — triggered when a tool touches paths outside the project working directory</li>\n<li><code>doom_loop</code> — triggered when the same tool call repeats 3 times with identical input</li>\n</ul>\n<hr />\n<h2 id=\"defaults\">Defaults</h2>\n<p>If you don’t specify anything, OpenCode starts from permissive defaults:</p>\n<ul>\n<li>Most permissions default to <code>\"allow\"</code>.</li>\n<li><code>doom_loop</code> and <code>external_directory</code> default to <code>\"ask\"</code>.</li>\n<li><code>read</code> is <code>\"allow\"</code>, but &quot;*.env&quot;: &quot;deny&quot;,\n      &quot;*.env.*&quot;: &quot;deny&quot;,\n      &quot;*.env.example&quot;: &quot;allow&quot;\n    }\n  }\n}\n</code></pre>\n<hr />\n<h2 id=\"what-ask-does\">What “Ask” Does</h2>\n<p>When OpenCode prompts for approval, the UI offers three outcomes:</p>\n<ul>\n<li><code>once</code> — approve just this request</li>\n<li><code>always</code> — approve future requests matching the suggested patterns (for the rest of the current OpenCode session)</li>\n<li><code>reject</code> — deny the
