A common pattern is to put the catch-all <code>\"*\"</code> rule first, and more specific rules after it.</p>\n<h3 id=\"wildcards\">Wildcards</h3>\n<p>Permission patterns use simple wildcard matching:</p>\n<ul>\n<li><code>*</code> matches zero or more of any character</li>\n<li><code>?</code> matches exactly one character</li>\n<li>All other characters match literally</li>\n</ul>\n<h3 id=\"home-directory-expansion\">Home Directory Expansion</h3>\n<p>You can use <code>~</code> or <code>$HOME</code> at the start of a pattern to reference your home directory. &quot;edit&quot;: {\n      &quot;~/projects/personal/**&quot;: &quot;deny&quot;\n    }\n  }\n}\n</code></pre>\n<p>Keep the list focused on trusted paths, and layer extra allow or deny rules as needed execution</li>\n<li><code>webfetch</code> — fetching a URL (matches the URL)</li>\n<li><code>websearch</code> — web search (matches the query)</li>\n<li><code>external_directory</code> — triggered
