## 3. Interfaces

**`errores.ts`:**
- `ErrorUso.codigo` pasa a ser `"almacen-sin-esquema" | "configuracion-invalida"`.
- Se agrega `errorConfiguracionInvalida(variable: string, motivo: string): ErrorUso`, cuyo mensaje nombra la variable y el motivo.
- `errorAlmacenSinEsquema` no cambia.

**`adaptadores/sistema/configuracion.ts`:**

```ts
export interface OpcionesConfiguracion {
  readonly entorno: Readonly<Record<string, string | undefined>>; // inyectado; nunca process.env adentro
  readonly rutaArchivo: string;                                   // ruta de rige.env; puede no existir
  readonly plataforma: string;                                    // valor de process.platform, inyectado
}
export class ConfiguracionSistema implements PuertoConfiguracion {
  constructor(opciones: OpcionesConfiguracion);
  leer(): Resultado<ConfiguracionRige, ErrorUso>;
}
```

Usá los tipos existentes `PuertoConfiguracion` y `ConfiguracionRige` (`aplicacion/puertos/configuracion.ts`) y `Resultado` (`nucleo/resultado.ts`). Sin cambiar sus firmas.

## 4. Reglas de comportamiento (una prueba por regla, con el ID en el `describe`)

| ID | Regla |
|---|---|
| C4-1 | Prelación por variable: entorno → `rige.env` → valor por defecto. Un valor vacío (tras recortar espacios) cuenta como no definido |
| C4-2 | `rige.env` se lee en forma explícita con `node:fs`. Si no existe, se usan el entorno y los valores por defecto, sin error |
| C4-3 | Formato del archivo: líneas `CLAVE=valor`; se ignoran las vacías y las que empiezan con `#`; se recortan espacios alrededor de la clave y del valor; sin comillas ni expansión. Una línea sin `=` da `configuracion-invalida`, nombrando el número de línea |
| C4-4 | En `rige.env` solo se admiten `RIGE_PUERTO` y `RIGE_ALMACEN`. Cualquier otra clave, incluidas `OPENCODE_*`, da `configuracion-invalida` y nombra la clave |
| C4-5 | Del entorno solo se leen `RIGE_PUERTO` y `RIGE_ALMACEN`. Las demás variables del entorno se ignoran |
| C4-6 | `RIGE_PUERTO`: solo dígitos, entero de 1 a 65535. Si no cumple, `configuracion-invalida` nombra `RIGE_PUERTO`. Por defecto, 4747 |
| C4-7 | `RIGE_ALMACEN` es un **directorio** y se devuelve como ruta absoluta (`resolve`). Por defecto: con plataforma `win32`, `<LOCALAPPDATA>\rige`; en cualquier otra, `<XDG_DATA_HOME>/rige` o, si no está, `<HOME>/.local/share/rige`, siempre a partir del entorno inyectado. Si falta la variable base (`LOCALAPPDATA` o `HOME`), `configuracion-invalida` la nombra |
| C4-8 | El adaptador no crea ni escribe nada: solo lee `rige.env` |

## 5. Pruebas

En `configuracion.test.ts`:
- el entorno es un objeto literal por prueba;
- los `rige.env` se crean en un directorio temporal (`mkdtempSync` en `os.tmpdir()`) que la prueba borra al terminar;
- nunca se modifica `process.env`;
- las reglas C4-7 se cubren para `win32` y para `linux`.
