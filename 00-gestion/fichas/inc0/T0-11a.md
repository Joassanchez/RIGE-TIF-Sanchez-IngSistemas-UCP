## 3. Interfaces

```ts
// aplicacion/respuestas/estado.ts — objeto de respuesta compartido (paridad CLI/web, ADR-058 conv. 1)
export interface RespuestaEstado {
  readonly esquema: 1;            // versión del esquema de salida (ADR-062 C5), no la de la base
  readonly versionRige: "0.1.0";
  readonly almacen: EstadoAlmacen; // ruta y versionEsquema de la base
}
export type RespuestaPreparacion = RespuestaEstado; // conserva el nombre de T0-09
export function respuestaEstado(almacen: EstadoAlmacen): RespuestaEstado;

// aplicacion/casos-uso/consultar-estado.ts
export function consultarEstado(almacen: PuertoAlmacen): Resultado<RespuestaEstado, ErrorUso>;

// adaptadores/sistema/existencia.ts — implementa el puerto que AlmacenSqlite ya exige (comentario en puertos/almacen.ts)
export class ExistenciaSistema implements PuertoExistenciaAlmacen {
  existe(ruta: string): boolean; // existsSync; no crea nada
}

// interfaces/cli/ejecutar.ts — no importa puertos, adaptadores ni núcleo (ADR-058)
import type { prepararAlmacen } from "../../aplicacion/casos-uso/preparar-almacen";
import type { ErrorUso } from "../../aplicacion/errores";
export interface CasosUsoCli {
  readonly prepararAlmacen: () => ReturnType<typeof prepararAlmacen>;
}
export type Ensamblado =
  | { readonly exito: true; readonly valor: CasosUsoCli }
  | { readonly exito: false; readonly error: ErrorUso };
export interface CanalesCli {
  escribirSalida(texto: string): void;
  escribirError(texto: string): void;
}
export function ejecutarCli(argumentos: readonly string[], ensamblar: () => Ensamblado, canales: CanalesCli): number;
```

**`arranque/rige.ts`** no exporta nada. Construye `ConfiguracionSistema` con `entorno: process.env`, `plataforma: process.platform` y `rutaArchivo: resolve(import.meta.dir, "../../../rige.env")`; define `ensamblar`, que lee la configuración (si falla, devuelve ese error), crea `AlmacenSqlite(directorioAlmacen, new ExistenciaSistema())` y devuelve `{ prepararAlmacen: () => prepararAlmacen(almacen) }`; y termina con `process.exitCode = ejecutarCli(process.argv.slice(2), ensamblar, canales)`, con los canales sobre `process.stdout.write` y `process.stderr.write`. No usa `process.exit`, no importa `node:fs` ni `bun:sqlite`, no captura excepciones y no llama a un caso de uso fuera de `ensamblar`.

**Formato de los canales:** un único JSON por línea, `JSON.stringify(valor) + "\n"`.
- Respuesta válida: el objeto `RespuestaEstado`.
- Error: `{"esquema":1,"error":{"codigo":"<codigo>","mensaje":"<mensaje>"}}`.
- Con `--depurar`, solo en la falla interna: `{"esquema":1,"error":{"codigo":"interno","mensaje":"…","stack":"<stack>"}}`.

## 4. Patrones existentes a imitar

- **Caso de uso:** imitá `aplicacion/casos-uso/preparar-almacen.ts`: función pura que recibe el puerto, devuelve `Resultado`, devuelve el **mismo objeto** de error del puerto sin envolverlo y no captura excepciones.
- **Prueba del caso de uso:** imitá `preparar-almacen.test.ts`. Usa dobles en memoria de `PuertoAlmacen`; el método que no debe llamarse lanza `new Error("No debe …")`; el error se compara con `toBe` y la excepción con `toThrow(falla)`.
- **Importación de errores y tipos en adaptadores:** solo a través del puerto. `puertos/almacen.ts` reexporta `errorAlmacenSinEsquema` y declara `PuertoExistenciaAlmacen`; `puertos/configuracion.ts` reexporta `errorConfiguracionInvalida` y `ErrorUso`. Un adaptador nunca importa `aplicacion/errores.ts` directamente.
- **Adaptador de sistema:** imitá `adaptadores/sistema/configuracion.ts`: imports nombrados de `node:fs` solo de lectura (`existsSync`), ruta absoluta con `node:path` y nada de `process.env` adentro.
- **Imports entre paquetes:** rutas relativas, como `../../../nucleo/resultado`; no uses `@rige/...`.
- **Temporales en pruebas:** imitá `adaptadores/almacen-sqlite/esquema.test.ts` y `adaptadores/sistema/configuracion.test.ts`: `mkdtempSync(join(tmpdir(), "rige-…"))` y borrado con `rmSync(…, { recursive: true, force: true })` al terminar cada prueba. Para crear la base con `user_version = 2` de la regla A-2, la prueba de aceptación puede abrir SQLite con `bun:sqlite`, porque la guarda de arquitectura excluye los `*.test.ts`.
- **Subprocesos:** el entorno sale de `crearEntornoAislado(temporal, process.env)` (`pruebas/utilidades/entorno-aislado.ts`), que hereda solo `PATH` y `SystemRoot`. A ese objeto le sumás solo las variables de la regla (`RIGE_ALMACEN`, `RIGE_PUERTO`). Lanzá `Bun.spawnSync([process.execPath, "paquetes/rige/arranque/rige.ts", …], { cwd: <raíz de src>, env, stdout: "pipe", stderr: "pipe" })`. **No uses `bun run`**: agrega sus propias líneas al canal de error, que no forman parte del contrato de RIGE.
- **Mensajes:** sin tildes, como `aplicacion/errores.ts`. Comentarios escasos, en español.

## 5. Reglas de comportamiento (una prueba por regla, con el ID en el `describe`)

| ID | Regla |
|---|---|
| E-1 | `consultarEstado` con un almacén compatible devuelve `{ esquema: 1, versionRige: "0.1.0", almacen }` con el `EstadoAlmacen` del puerto; llama solo a `consultar`, nunca a `preparar` |
| E-2 | Si `consultar` devuelve `almacen-sin-esquema`, `consultarEstado` devuelve ese mismo objeto (`toBe`), cuyo mensaje nombra `bun run esquema`, sin llamar a `preparar` |
| E-3 | Una excepción de `consultar` se propaga sin convertirse en error de uso |
| E-4 | Paridad: con el mismo `EstadoAlmacen`, `prepararAlmacen` y `consultarEstado` devuelven valores iguales (`toEqual`), construidos con `respuestaEstado` |
| S-1 | `ExistenciaSistema.existe` da `true` para un archivo temporal existente y `false` para una ruta inexistente, sin crearla |
| CLI-1 | `["esquema"]` con ensamblado y caso de uso exitosos: salida = `JSON.stringify(respuesta) + "\n"`, error vacío, código 0 |
| CLI-2 | Error de uso del ensamblado (`configuracion-invalida`) o del caso de uso (`almacen-sin-esquema`): salida vacía, error = JSON de error con ese código y mensaje, código 1 |
| CLI-3 | Argumentos inválidos: sin subcomando, subcomando desconocido (`otro`), dos posicionales u opción desconocida (`--x`). Salida vacía, JSON de error `argumentos-invalidos`, cuyo mensaje nombra lo inválido, y código 2. `ensamblar` **no** se llama. Los errores de `parseArgs` dan 2, nunca 70 |
| CLI-4 | Excepción en `ensamblar` o en el caso de uso: salida vacía, JSON de error `interno` con mensaje fijo, sin el mensaje ni el stack de la excepción, y código 70. Se captura una sola vez, en `ejecutarCli` |
| CLI-5 | `--depurar` (antes o después del subcomando) agrega `stack` solo en la falla interna; en los casos 0, 1 y 2 la salida es idéntica con y sin la opción |
| A-1 | Subproceso `esquema` con `RIGE_ALMACEN` en una carpeta inexistente: código 0, stderr vacío, stdout JSON con `almacen.ruta` = `<carpeta>/rige.db` (separador `/`) y `versionEsquema` 1. Una segunda ejecución da el mismo stdout, byte a byte |
| A-2 | Subproceso con `RIGE_PUERTO=abc`: código 1, stdout vacío, stderr JSON `configuracion-invalida` que nombra `RIGE_PUERTO`. Con una base existente de `user_version = 2`: código 1, `almacen-sin-esquema` y mensaje con `bun run esquema`; después, la base sigue en `user_version = 2` |
| A-3 | Subproceso `otro`: código 2, stdout vacío, stderr JSON `argumentos-invalidos` |
| A-4 | Subproceso `esquema` con `RIGE_ALMACEN` apuntando a un **archivo** regular: código 70, stdout vacío, stderr JSON `interno` sin `stack`; con `--depurar`, con `stack`. El temporal no tiene archivos nuevos después de las dos corridas (sin logs a disco) |

## 6. Pruebas

- **Unitarias** (E, S, CLI), junto al código. La CLI se prueba con `ensamblar` y casos de uso dobles y canales que acumulan texto; sin subprocesos ni E/S.
- **Aceptación** (A), en `pruebas/aceptacion/arranque.test.ts`, por subproceso según §4. Cada prueba usa su propio temporal y lo borra. Nunca se usa el almacén real, el puerto 4747 ni `process.env` modificado.
- El rojo de cada regla se observa antes del código. Si el código ya la satisface, se observa con una mutación temporal revertida y así se registra.

## 8. Resultado esperado y detención

- **Pruebas:** `bun test` completo en verde (base: 225 pasan antes de T0-10, más las de T0-10). **`verificar`:** **tiene que pasar**: tipos de los cuatro proyectos y `bun build` de `arranque/rige.ts`, con salida 0. Es la primera tarea en la que `verificar` da PASS.
- **Commit:** mensaje `feat: estado, contrato de la CLI y arranque (T0-11a)`, con una línea rojo → verde por regla (E-1 a A-4) y el resultado final de `bun test` y `verificar`. Agregá solo los archivos de §2.
- **Respuesta final:** el JSON del esquema `../00-gestion/fichas/esquema-salida-escritor.json`.
- **Detenete sin commitear** (estado `detenida`, con la pregunta y la opción que proponés) si:
  - una regla contradice un ADR;
  - hace falta tocar otro archivo (incluidos `package.json` o la guarda de arquitectura) o agregar una dependencia;
  - una prueba de arquitectura falla y la solución exige relajarla;
  - `bun build` no resuelve la importación del `.sql` desde el arranque;
  - en esta plataforma, un `RIGE_ALMACEN` que apunta a un archivo regular no produce una excepción (A-4).
