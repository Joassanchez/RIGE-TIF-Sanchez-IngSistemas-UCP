## 1. Qué hay que hacer

Todas las rutas de la web pasan por `conVerificacionDeOrigen`, que va dentro de `conErrores` y antes del enrutador. Ese intermediario aplica tres controles:
- solo atiende `Host` local con el puerto propio;
- solo atiende GET;
- rechaza `Sec-Fetch-Site` entre sitios.

Ninguna respuesta lleva cabeceras CORS. Se prueba en forma exhaustiva el escape de las plantillas. Con esto quedan acreditados RNF-09 CA-1, CA-2 y CA-3 y ADR-062 C2 y C7. **No** se hace en esta tarea: el README (T0-13) ni rutas nuevas.

## 3. Interfaces

```ts
// interfaces/web/intermedios/origen.ts
export function conVerificacionDeOrigen(
  puerto: number,
  manejador: (solicitud: Request) => Response,
): (solicitud: Request) => Response;

// interfaces/web/servidor.ts — cambia la firma; iniciarServidor le pasa su puerto
export function crearManejador(puerto: number, consultar: ConsultarEstado): (solicitud: Request) => Response;
// = conErrores(conVerificacionDeOrigen(puerto, enrutar)), con enrutar = la lógica actual de rutas
```

**Orden de los controles en `conVerificacionDeOrigen`:** `Host` → `Sec-Fetch-Site` → método. El primero que falla responde sin llamar al manejador interno.
- **`Host`:** se admite solo `127.0.0.1:<puerto>` o `localhost:<puerto>`, comparados en minúsculas con el puerto propio. Cualquier otro valor (otro nombre, otro puerto, sin puerto, `localhost.`, `[::1]`) o la ausencia de la cabecera → **403**.
- **`Sec-Fetch-Site`:** lista de admitidos: ausente, `same-origin` o `none`. Cualquier otro valor, incluidos `cross-site`, `same-site` y valores desconocidos → **403**.
- **Método:** solo `GET`. Cualquier otro, incluidos `HEAD` y `OPTIONS` → **405** con `Allow: GET`.

Todo rechazo usa la misma página fija `Solicitud rechazada.` (`text/html; charset=utf-8`), sin datos del estado. Ninguna respuesta, ni válida ni de rechazo ni de error ni de ruta inexistente, lleva cabeceras `Access-Control-*`.

**Decisiones del ingeniero para esta tarea (no están en los ADR):**
- Los códigos de rechazo son 403 para `Host` y `Sec-Fetch-Site` y 405 para el método.
- El `Host` se compara sin distinguir mayúsculas.
- `Sec-Fetch-Site` se trata como lista de admitidos: un valor desconocido se rechaza.
- `paginaErrorUso` sigue respondiendo 503 para todo error de uso; hoy solo llega `almacen-sin-esquema`.

## 5. Reglas de comportamiento (una prueba por regla, con el ID en el `describe`)

| ID | Regla |
|---|---|
| O-1 | `Host`: `127.0.0.1:<p>`, `localhost:<p>` y `LocalHost:<p>` pasan al manejador. `127.0.0.1:<otro>`, `ajeno.example:<p>`, `127.0.0.1` sin puerto, `localhost.:<p>`, `[::1]:<p>` y la cabecera ausente → 403, página `Solicitud rechazada.` y el manejador no se llama |
| O-2 | `Sec-Fetch-Site`: `cross-site`, `same-site` y `desconocido` → 403 en `/` y en `/otra`. Ausente, `same-origin` y `none` → pasan |
| O-3 | Método: `HEAD`, `POST`, `PUT`, `DELETE`, `PATCH` y `OPTIONS` → 405 con `Allow: GET` y el manejador no se llama. `GET` pasa |
| O-4 | `crearManejador` aplica los controles a toda ruta, incluida la inexistente. Ninguna de estas respuestas lleva una cabecera cuyo nombre empiece con `access-control-`: 200, 404, 403 de `Host`, 403 de `Sec-Fetch-Site`, 405, 503 de error de uso y 500 de excepción en `consultar` |
| P-1 | Plantillas: cada uno de `& < > " '` se escapa por separado. `&amp;` da `&amp;amp;`. Un `html` anidado se inserta sin doble escape. Un arreglo que mezcla `HtmlSeguro` y texto no deja ningún `<` sin escapar. Los números, `null` y `undefined` se presentan como texto |
| P-2 | En `paquetes/` no hay llamadas a `sinEscapar` cuyo argumento no sea un literal de cadena simple (sin interpolación). La prueba recorre los `.ts` de `paquetes/rige/interfaces/web` y falla ante una sonda temporal con argumento variable |
| RNF-09 CA-1 | Subproceso `servir`. `GET /` con `Host: ajeno.example:<p>` y con `Host: 127.0.0.1:<otro>` → 403, y el cuerpo no contiene «RIGE 0.1.0» ni la ruta del almacén. Con `Host: localhost:<p>` → 200 |
| RNF-09 CA-2 | Subproceso `servir`: `POST`, `PUT`, `DELETE` y `HEAD` sobre `/` → 405; `GET` → 200 |
| RNF-09 CA-3 | Subproceso `servir`. En las respuestas de CA-1 y CA-2, en `GET /otra` (404) y en `GET /` con `Sec-Fetch-Site: cross-site` (403) no aparece ninguna cabecera `access-control-*` |
| C7-1 | Subproceso `servir`: `Sec-Fetch-Site: cross-site` y `same-site` → 403 en `/` y en `/otra`; `same-origin` y `none` → 200 en `/` |
| C2-1 | Subproceso `servir` con `RIGE_ALMACEN` en una carpeta llamada `a&b'c`. `GET /` → 200, el cuerpo contiene `a&amp;b&#39;c` y no contiene `a&b'c` |

## 6. Pruebas

- **Unitarias** (O, P), junto al código, puras: `Request` y `Response` en memoria, sin servidor. P-2 lee archivos fuente: es una guarda estática, no lanza subprocesos.
- **Aceptación** (RNF-09, C7-1, C2-1), en `pruebas/aceptacion/RNF-09.test.ts`, por subproceso, con puerto libre en cada corrida (nunca 4747) y `RIGE_ALMACEN` en un temporal. Se puede levantar un solo servidor por `describe` y cerrarlo en `afterAll`, siempre que ninguno quede vivo.
- El rojo de cada regla se observa antes del código. Si el código ya la satisface (por ejemplo, P-1 o CA-3), el rojo se observa con una mutación temporal revertida y así se registra.
